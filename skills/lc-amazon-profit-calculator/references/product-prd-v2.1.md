# 易逊-亚马逊商品毛利计算 · 产品需求文档

- 文档版本：v2.1
- 对应 Skill 版本：2.1.0
- 中文显示名称：易逊-亚马逊商品毛利计算
- 技术标识：`lc-amazon-profit-calculator`
- 文档日期：2026-10-25
- 文档性质：以当前实现为基线的产品规格与后续验收依据。
- 核心定位：亚马逊选品前期的单商品毛利参考工具。

本文件描述当前已实现流程、业务规则及明确限制，不把待核验费率或建议改进写成已交付能力。界面及 Skill 的功能版本为 2.1，快速测算数据格式继续使用 `schemaVersion: "2.0"`。

## 1. 背景与问题

运营在选品前期需要快速判断一个商品或同类型产品是否具备利润空间，并比较不同头程渠道和仓储费用条件下的表现。输入通常是一个 Amazon 链接，以及少量供应链和经营参数。

原有流程的问题：

- 反复询问广告税费、外箱、装箱空隙、入仓日期和账户费用，前期决策成本过高。
- 自动采集、缺项补充、人工确认和计算之间切换频繁。
- 静态报告可以调参，但修改不自动保存，刷新后可能丢失。
- 根据每次运行日期推算淡旺季，降低不同商品之间的可比性。
- 运营必须在聊天中填写参数，无法在一个页面连续比较方案。

当前方案将采集交给 Agent、公式交给代码、手动补充交给 HTML 表单，形成可恢复的本地测算会话。

## 2. 产品目标

### 2.1 核心目标

1. 用户提供商品链接后，尽可能自动读取售价、变体、类目、尺寸、重量和站点信息。
2. 常规只需要手动补充采购成本、至少一条头程报价、缺少可信来源的退货率。
3. 自动取数后立即在 Codex 内打开填写页面，不等待用户在聊天中补齐经营参数。
4. 数据齐全后即时输出淡季、旺季两组仓储情景毛利，并同步比较已报价渠道。
5. 每次修改自动保存；刷新、重新打开、服务重启后可恢复已保存的输入与结果。
6. 结果提供数据来源、默认值、估计依据和排除费用，支持可靠的前期判断。

### 2.2 不属于本版本的目标

- 完整店铺利润、会计利润、企业税务或真实账单核算。
- FBM、跨国 FBA、泛欧库存网络或复杂税务架构核算。
- 关键词、市场趋势、评论情感、销量预测或选品推荐。
- 外箱、装箱数量、包装空隙、最低计费重等精细货代结算。
- 按真实运输日期生成库存日历、现金流计划和补货计划。
- 多用户云端协作、账号权限系统、云同步及跨设备自动保存。
- 自动根据结果采购、下单、创建货件或向第三方发送信息。

## 3. 用户与核心场景

### 3.1 目标用户

- 选品人员：比较候选产品毛利空间，识别明显亏损方案。
- 运营人员：调整售价、广告和退货率，观察利润变化。
- 采购及负责人：核对供应商报价与不同物流方案的利润承受能力。

### 3.2 核心场景

**场景 A：仅提供链接。** 自动取数后打开草稿页面，核心经营字段为空；用户在页面填写后完成测算。

**场景 B：链接和经营参数一起提供。** 复用本次请求中已有参数，打开页面时直接显示完整结果，不重复询问。

**场景 C：只提供一条物流报价。** 只计算该渠道，允许后续添加其他报价；不要求四条渠道齐全。

**场景 D：商品页缺少尺寸。** 在“商品资料与包装”中展开缺失字段，允许用户补填，不用同类商品尺寸静默代替。

**场景 E：已经填写，稍后继续。** 重新打开同一任务页面，恢复最后保存的参数、主渠道和结果。

**场景 F：报价或售价发生变化。** 本地重算相关成本和两种仓储情景，跨费率档位时重新匹配，不继续显示旧档位费用。

## 4. 范围与支持站点

保留 11 个站点：US、JP、UK、DE、FR、IT、ES、SA、MX、CA、AU。站点由链接识别，不能将无法识别的链接自动当作美国站。

- 商品详情工具可用于其枚举支持的站点；沙特使用当地商品页，不用阿联酋站代替。
- 每个站点具有独立佣金、配送、基础仓储、退货及必要价内销售税规则。
- 站点支持表示具备该站点的数据和计算路径，不表示所有类目、尺寸、账户资格、危险品和特殊税种均完整覆盖。
- 新商品可复用费率缓存，不可自动复用上一商品的采购、物流报价和退货率。
- 同一 ASIN 的新测算使用新目录；继续原任务才复用原目录。

## 5. 完整用户流程

```text
用户提供链接及可选资料
  → 识别站点、ASIN和已有参数
  → 单商品详情工具取数
  → 商品页补充缺失字段
  → 准备输入，检查费率与汇率缓存
  → 启动本地填写服务
  → Codex 内置浏览器打开页面
  → 用户修改或补充参数
  → 本地即时校验、计算双情景
  → 自动保存草稿或完整结果
  → 刷新 / 重开时恢复
```

### 5.1 聊天与页面的职责

- 聊天负责发起任务、解释无法自动处理的问题、重新打开页面和读取已保存结果。
- 页面负责常规经营参数输入、商品资料修正、渠道选择、结果展示和保存状态。
- 不用聊天重复确认表单已有值，不要求用户填写完后回到聊天说“完成”。
- 当前本地服务不会自动向聊天发送完成通知；需要文字分析时，Agent 读取已保存结果再回复。

### 5.2 主流程完成条件

- 页面已在 Codex 内实际打开，目标商品和已采集字段正确。
- 尚缺手填项时，页面明确显示草稿与缺项；不能宣称已经算出毛利。
- 用户补齐后，双情景结果可见，保存状态成功，任务目录存在一致的输入、结果及报告。

## 6. 自动采集需求

### 6.1 数据优先级

1. 本次用户明确提供或修正的数据。
2. 当前目标变体的可信商品页资料。
3. 单 ASIN 商品详情工具返回的适用数据。
4. 明确标注的近似值及团队默认经营参数。

出现冲突时保留来源和适用说明。不能将其他 ASIN、站点或变体的尺寸、重量混入目标商品。

### 6.2 自动读取字段

- 站点、币种、ASIN、商品名称、链接。
- 可确定的目标变体，例如颜色和尺码。
- 单次购买公开售价及明确适用的公开优惠。
- 销售包装数量、销售单位及收费类目。
- 包装长宽高、包装重量；缺失时读取商品尺寸、净重作为近似依据。
- 数据来源、采集时间或工具数据更新时间。

### 6.3 售价口径

- 默认使用公开单次购买价格。
- 明确且无条件的公开折扣可自动计入。
- Prime 专享、订阅、信用卡、领取后优惠等不作为默认价格静默扣除。
- 用户已指定成交价格时，不再次扣减采集优惠。
- 无法取得有效价格时保留空值，在页面补填，不使用价格区间中点或其他变体价格冒充。

### 6.4 尺寸、重量和销售包装

- 优先使用一个销售包装的尺寸和毛重。
- 只有商品尺寸、净重时允许近似计算，标记“含近似包装参数”。
- 三维尺寸必须齐全且大于零，不将缺失第三维补为 1cm。
- 不增加外箱体积、包装间隙、箱重和额外重量余量。
- 多件装的采购、重量、尺寸均按整销售包装，公式不再重复乘件数。
- 仅描述内装单件的尺寸不能当作整包尺寸。

### 6.5 限制无关采集

不调用关键词、趋势、评论或其他与毛利公式无关的工具。退货率不能由评分、评论数量、评论语义或主观品类印象推断。

## 7. 参数与校验

### 7.1 核心经营字段

- 采购成本：人民币/销售包装，允许明确填写 0；缺失为空，不从其他商品复制。
- 头程单价：人民币/kg，至少一个有效报价；明确的 0 与未提供区分。
- 退货率：页面填写百分比，内部存 0–1 比例；必须满足 `0 ≤ r < 1`。

### 7.2 可修改默认值

- 广告占比：10%。
- 退货不可售比例：20%，必须在 0%–100% 之间。
- 平均仓储天数：90 天，允许非负数。
- 头程体积系数：快递 5000，空运、快船、慢船和泛海运 6000。

修改只影响本次测算，不更新团队默认值。广告占比的当前计算校验为非负数；超过 100% 可表示高广告消耗，不等同于退货率规则。

### 7.3 页面可修正的商品字段

- 售价：大于零，以站点币种计。
- 当前变体/规格：说明性文字。
- 商品收费类目：已有选项或输入中已有类目。
- 每销售包装件数：正整数。
- 包装长宽高：cm，三个正数。
- 包装重量：kg，正数。
- 参数依据：“销售包装资料”或“商品尺寸/净重近似”。

站点、币种、ASIN、费率包、汇率和费用表达式不能通过常规表单任意改写。修改规格文字不等于自动切换 ASIN，也不会重新抓取另一变体；换商品或变体链接应发起新的采集。

### 7.4 空值与无效值

- 空白保存为 `null`，不是 0。
- 缺项和业务范围无效的输入可以保存为草稿。
- 结果所需关键参数无效时隐藏完整结果，避免旧毛利继续被误读。
- 只填一部分尺寸也应保存；维度草稿使用三个槽位，未填位置为 null。
- 非法比例草稿重新打开时仍应显示可修正表单，不导致整页崩溃。

## 8. 页面结构与交互

### 8.1 信息架构

- 页头：任务用途、恢复打开时参数、导出参数、打印/PDF。
- 填写区：采购成本、退货率、物流渠道与报价。
- 可展开设置：其他经营参数、商品资料与包装、头程计费系数。
- 保存区：“计算并保存”、保存状态和本地重算状态。
- 结果区：商品身份、参考依据、淡旺季毛利、毛利率、仓储费和差额。
- 对比区：已报价渠道比较、费用拆分、保本广告占比。
- 折叠说明：来源、默认值、估计依据、公式、排除费用。

桌面以填写区和结果区并列展示；窄屏先填写后结果。金额显示站点币种，利润率与金额并列，亏损有明确视觉提示。

### 8.2 物流报价

- 无报价时显示一条空白“海运”行，不填默认单价。
- 可切换快递、普通空运、快船、慢船、海运，可增加或删除渠道。
- 当前结构每种渠道一个报价；同渠道多个货代报价不是本版能力。
- 只计算已填写的渠道，不要求补齐全部渠道。
- 若新增一条报价但未填写数值，该行属于当前缺项；可补全或删除后恢复完整结果。
- 未指定主渠道时，按淡季参考毛利排序选择；同一商品两季只改变仓储项，渠道比较使用相同业务参数。
- 用户点击渠道切换主结果和成本拆分。该选择也保存。

### 8.3 输入后的反馈

1. 每次输入即本地校验并更新两组结果。
2. 停止输入约 500ms 后自动保存。
3. “计算并保存”立即发起校验和保存，无需等待防抖计时。
4. 本地算出结果不等同于已写入磁盘；保存状态独立展示。

### 8.4 缺项提示

- 中文字段名和就地提示，不直接用内部 JSON 路径作为用户指引。
- 缺价格、尺寸等商品字段时自动展开相关补填区。
- 缺少平台规则或汇率时单独提示“平台资料待补充”，由 Agent 查询。
- 不让用户填写完整费表，不将未知费用填零以便通过校验。
- 费用预检使用临时参数探测覆盖，不写入真实经营输入，也不生成用户毛利金额。

## 9. 计算口径

### 9.1 计算单位

所有主指标按一个最终未退款的销售包装表示。采购和头程按一个销售包装填写；退货相关费用及报废投资通过分摊进入最终留存销售单位。

该“参考毛利”包含广告和退货损失，是选品运营口径；不等同于财务报表中的会计毛利或企业净利润。

### 9.2 变量定义

- `P`：销售包装售价，站点币种。
- `t`：必要的价内销售税率。
- `R`：销售净收入。
- `e`：一单位当地币种对应的人民币金额。
- `c`：采购成本，人民币/销售包装。
- `w`：包装重量，kg。
- `V`：单销售包装体积，cm³。
- `q`：头程报价，人民币/kg。
- `d`：所选头程体积系数。
- `a`：广告占比；`r`：退货率；`u`：退货不可售比例。
- `n`：仓储天数；`k`：仓储费率的体积换算单位。
- `s_low`、`s_peak`：淡旺季月仓储费率。

### 9.3 收入与成本

```text
R = P / (1 + t)
C = c / e
H = max(w, V / d) × q / e
M = 站点佣金规则(P, 类目)
F = 站点常规FBA规则(售价, 类目, 尺寸, 重量)
S_low  = V / k × s_low  × n / 30
S_peak = V / k × s_peak × n / 30
A = R × a
```

头程体积重与 FBA 计费独立。不能因为头程用 6000，就给 FBA 套用 6000；FBA 按当地规则选实重、体积重、尺寸等级和重量档位。

### 9.4 退货分摊

```text
L = 不可退回的原FBA配送费 + 退款管理费 + 适用退货处理费
D = r / (1 - r) × [L + u × (C + H + S)]
```

- `r = 退货数 / 发货数`；`u = 不可售退货数 / 退货数`。
- `r = 0` 时退货损失分摊为 0，不要求无关退货费用金额。
- `r = 1` 没有留存销售单位，不可计算。
- 退款本金不再次直接扣除，广告不在退货分摊中重复加入。
- 采购、头程和仓储的不可售投资只按不可售退货比例分摊。
- 账户门槛未知的退货处理费用，采用有来源且可解释的保守估计并标注；没有依据就保持缺项。

### 9.5 毛利与辅助指标

```text
G = R - C - H - M - F - S - A - D
参考毛利率 = G / R
广告前参考利润 = G + A
保本广告占比 = (G + A) / R
人民币参考毛利 = G × e
旺季相对淡季毛利变化 = G_peak - G_low
```

毛利率差异以百分点展示，不能与相对变化百分比混淆。保本广告占比只是当前模型的盈亏平衡参考，不代表推荐投放比例。

### 9.6 双仓储情景

- 两个情景使用相同售价、广告、退货、物流和常规配送规则。
- 只切换基础仓储月费率，然后分别重算全部成本和退货分摊。
- 无季节仓储差价时，两个结果一致。
- 不输入或推演发货、入仓和售出日期。
- 旺季配送附加费不混入“仓储情景”差异。

### 9.7 独立手算示例

以下为公式验收样本，不是实际商品估计：发货 100、退货 25、留存 75、不可售 5；每次退货费用 8、采购 10、头程 2、仓储 3。

```text
D = (25 × 8 + 5 × (10 + 2 + 3)) / 75
  = 3.666666667
```

仓储升至 6 时，D 为 3.866666667。因此每个留存销售单位的毛利减少 3.2，而不是只减少仓储差价 3。

## 10. 费用范围与排除项

默认纳入：采购、头程、佣金、常规 FBA 配送、基础仓储、广告、退货损失。站点费表中适用的常规燃料等配送加价按规则保留。

默认排除并统一展示“本测算未包含”：

- 广告及平台服务税的单独核算。
- 外箱、装箱间隙和重量余量。
- 入库配置、计划外服务。
- 低库存、仓储利用率、超龄库存附加费。
- 弃置、移除费。
- 旺季配送附加费。
- 提现、汇兑价差、企业所得税和其他账户费用。

“未包含”不是“实际为零”。站点公开费率本身包含的税项不重复加收；必要的价内销售税仍从售价中还原一次，避免含税价直接当净收入。

## 11. 费率、汇率与规则维护

### 11.1 来源与可追溯要求

费率包保存站点、版本、来源、生效时间、检查时间、适用类目/尺寸/重量档位和计算表达式。来源优先官方公开帮助、费率卡和计算器，其次为可追溯第三方估计。

每个测算输入冻结当次采用的费率与汇率，便于复算。报告展示来源和检查日期，不因重复打开而悄悄改变历史利润。

### 11.2 更新策略

- 新任务费率超过 7 天未检查，自动抓取来源并核对已审定内容哈希。
- 与已审定来源一致时，可延长检查日期。
- 内容变更、登录页、空壳或抓取失败不能直接认定规则已更新；交由 Agent 复核。
- 已知失效或尚未生效的规则阻止计算。
- 暂时无法刷新且未已知失效的缓存可作为明确标注日期的条件参考。
- 汇率缓存有效期 24 小时；公开 CNY 参考汇率不得冒称 CNH 结汇价。
- 调整采购、广告、退货、报价或仓储天数时不重新联网。

### 11.3 参数依赖

- 采购变化：重算采购及退货报废分摊。
- 报价或体积系数变化：重算头程及相关退货分摊。
- 广告变化：重算广告成本和利润。
- 退货变化：重算分摊及适用阈值费用。
- 仓储天数变化：重算两季仓储及报废分摊。
- 售价变化：重算净收入、佣金、低价配送资格、广告和退款管理费。
- 尺寸或重量变化：重新匹配头程、配送、仓储等级和适用退货档位。

固定费用估计必须绑定适用条件，越过绑定条件后提示规则需要更新；改采购价不能使不相关费用估计失效。

### 11.4 当前覆盖边界

- 美国：普通商品常见标准包装、服装/非服装配送分档、鞋服等退货规则及双仓储费率。
- 英国、德国、法国、意大利、西班牙：当地常规与低价档、鞋服规则、必要价内税及仓储；德国按当前 DE Only 模式。
- 加拿大：当地标准包装配送、低价条件、仓储、鞋服退货，不能直接套用美国表。
- 日本：当地尺寸/重量档、低价条件、分品类仓储和退款规则；部分电子配件需继续识别细分类目。
- 墨西哥：当地售价档、体积重、仓储及退款规则。
- 沙特：常规 FBA 和仓储有官方依据；额外退货处理采用有来源第三方区间上端保守估计，持续标注。
- 澳洲：已具备常规配送、佣金、仓储和退款管理规则；非零退货率下缺少可靠额外退货处理金额时，仍阻止输出完整毛利。

具体费率值以随 Skill 保存的费率包及其来源为准。本文不是独立最新费表，不把 11 站点路径可用解释为所有 SKU 全覆盖。

## 12. 自动保存与状态管理

### 12.1 用户可见状态

- 待填写：存在关键缺项，显示补填指引。
- 尚未保存：本页存在新修改。
- 保存中：请求正在提交。
- 草稿已保存：输入已落盘，但不能形成完整结果。
- 已保存：当前有效输入和结果已落盘。
- 保存失败：保留本页输入，支持重试，不显示为成功。
- 版本冲突：其他页面已写入更新版本；保留当前编辑，先导出，再刷新对照修改。

### 12.2 请求顺序

- 浏览器保存请求串行发送；保存期间再次输入，完成当前请求后提交最新快照。
- 每次请求携带 revision，服务端只接受当前版本。
- 旧请求不能覆盖新版本，不做未经用户理解的自动多页面合并。
- 保存请求设置超时，防止无限显示保存中。
- 有未保存改动时关闭或刷新页面，应触发浏览器离开提示；不能保证用户强制关闭后恢复尚未提交的输入。

### 12.3 文件落盘与恢复

- `bundle.json`：采集原始数据及已有用户参数。
- `input.json`：最新保存的标准化输入和规则快照。
- `result.json`：服务端共享引擎生成的结果，不手工改金额。
- `report.html`：可独立打开、可本地调参的报告快照。
- `ui-state.json`：权威会话草稿，包含输入、revision、savedAt 和会话格式版本。

写入先暂存各文件，再替换；普通写入失败尝试恢复已替换文件，ui-state 最后提交。该机制不是跨文件数据库事务；异常中断后以 ui-state 为准重建派生文件。

### 12.4 服务生命周期

- 同一目录优先复用已运行服务，未运行则从已保存状态恢复。
- 原 bundle 的新内容不覆盖既有草稿；重算新方案或替换费用快照时使用新目录。
- 页面每分钟保活，最后请求后约 30 分钟空闲退出。
- 本机服务停止后，需要通过 Skill 重新启动；旧页面不能在服务关闭时自动写入磁盘。
- 自动保存在线页面与离线报告明确区分：离线报告修改仅保留本页，需导出参数。

## 13. 技术实现与接口约束

### 13.1 模块职责

- `SKILL.md`：采集、页面启动、费用异常和交付的执行规则。
- `scripts/cli.cjs`：统一命令入口，区分快速输入和旧版输入。
- `scripts/quick-cli.cjs`：准备快照、批量生成结果与 HTML。
- `scripts/quick.js`：单位换算、默认值、校验、费率匹配、双情景及费用预检。
- `scripts/engine.js`：共享 Decimal、规则解释器及原版计算能力。
- `scripts/cache.cjs`：费率、汇率缓存和更新检查。
- `scripts/ui-server.cjs`：本地服务、会话复用、版本控制、白名单和持久化。
- `assets/quick-report.html`、`quick-report-app.js`：填写和结果界面。
- `data/rates/`、`data/fx.json`：规则和汇率缓存。
- `tests/`：历史回归、快速流程、费率边界及本地 HTTP 测试。

无需新增前端框架或 npm 安装步骤；本地服务使用 Node 标准库，计算使用已有 Decimal 和共享引擎。

### 13.2 主入口

```text
identify <Amazon URL>
ui <bundle或v2-input.json> <任务输出目录>
prepare <bundle.json> <input.json>
run <bundle或v2-input.json> <输出目录>
refresh <SITE>
```

`ui` 成功输出 ready、本地 URL 和目录，即使缺手动参数也以成功结束启动命令。随后必须通过 `open_in_codex` 的 browser 目标打开完整 URL，不能用 HTML 源码页代替填写界面。

### 13.3 本地 HTTP 接口

- `GET /`：返回嵌入当前草稿与 revision 的 HTML。
- `GET /api/state`：需 `X-Session-Token`，读取当前输入、结果和保存版本。
- `POST /api/save`：需同源 Origin、令牌、JSON 请求体 `{revision, editable}`；服务端合并白名单字段并重新计算。
- 400：无效 JSON 或不允许修改的字段；403：令牌、Origin 或 Host 不符合；409：版本冲突；413：请求过大；415：内容类型不正确；500：保存失败。

输入业务缺项与协议错误不同：业务缺项允许保存草稿，不能仅因采购或退货未填就将整个保存请求当作协议错误。

### 13.4 标准化输入与精度

快速输入包含 schemaVersion、kind、asOf、product、scenario、logistics、feePack、fx、fieldMeta、notes、excluded 和 source。asOf 是测算资料时间，不是发货日期；product 保存商品资料，scenario 保存经营参数，logistics 按渠道键保存报价。

fieldMeta 区分 extracted（采集）、user（用户修改）、default（默认）、estimated（估计）和 missing（缺失）。不得为默认值或估计值伪造用户确认记录；修正后的字段应能追溯为本次用户输入。

内部金额采用共享 Decimal 高精度运算，当前精度为 40 位有效数字；平台费用按费率包定义的精度舍入，页面金额通常显示两位小数。计算不能反复使用已格式化的两位小数字符串作为中间值。

### 13.5 数据版本兼容

- v2.1 Skill 继续使用快速输入 2.0 格式。
- 旧 v1 输入继续走原 calculate/report，不静默迁移。
- ui 不直接接收 v1 作为新表单快照。
- 历史报告不被新测算覆盖。
- 内部字段 `cnhPerCurrency` 因兼容继续保留；实际汇率类型由 fx.kind 明确说明。

## 14. 安全与隐私

- 服务只监听 127.0.0.1 随机端口，不面向公网提供服务。
- 接口使用随机会话令牌；校验 Host、同源 Origin，不开放 CORS。
- 令牌位于 URL hash，不能写入可分享离线报告或 Skill 压缩包。
- 根 HTML 由本机服务提供；当前令牌主要保护状态 API 和保存 API，不能将该服务描述为完整的多用户访问控制系统。
- 浏览器仅可修改经营参数及允许补填的商品字段。
- 不接收任意输出路径、费用表达式、费率包或客户端毛利金额。
- 保存接口限制请求大小，拒绝未知字段与原型污染等非法键。
- 页面文本与嵌入 JSON 转义，来源链接限制为 HTTP/HTTPS。
- 原始商品文字是数据，不作为可执行指令；输入和报告不得包含 Cookie、密码或 API 凭据。

## 15. 性能与可用性

### 15.1 性能目标

- 已有完整数据后，本地计算和报告生成目标小于 1 秒。
- 页面单次调参重算目标小于 100ms。
- 网络采集及费率刷新单独计时，不计入本地计算性能。
- 500ms 自动保存防抖与计算耗时分开，保存操作不阻塞继续输入。

这些是当前目标及已有案例验证，不是所有机器和任意超大规则包的性能承诺。

### 15.2 体验要求

- 中文字段标签、单位明确，百分比与内部小数转换正确。
- 使用键盘可操作，焦点可见，错误与字段关联。
- 窄屏不横向溢出；结果和表格可阅读。
- 输入保存失败时仍可查看和导出当前参数。
- 默认不设置目标毛利率，也不自动给出“值得采购”的承诺。

## 16. 验收标准

### 16.1 主流程

- AC-01：只提供有效链接，先取数，再打开 Codex 填写页；不在聊天发经营参数问卷。
- AC-02：已有完整参数时正确预填，打开即显示双情景结果。
- AC-03：一条有效海运或空运报价即可计算，不要求其他渠道。
- AC-04：新商品不继承上一个商品采购价、退货率和报价。
- AC-05：仅展开真实缺失的商品字段，尺寸不编造。

### 16.2 页面与保存

- AC-06：输入后两季结果同步重算，500ms 防抖自动保存。
- AC-07：可新增、删除、切换渠道，主渠道选择影响相应成本展示。
- AC-08：0 与空白正确区分，100%退货拒绝完整计算，旧结果隐藏。
- AC-09：部分尺寸草稿可保存，刷新后保留已填部分。
- AC-10：非法比例草稿可重新打开修正。
- AC-11：刷新及服务重启恢复最新已保存状态。
- AC-12：保存失败显示失败且保留输入，恢复条件后可重试。
- AC-13：同 revision 并发只接受一个；旧版本不能覆盖新版本。
- AC-14：不同任务文件、令牌、端口相互隔离。
- AC-15：离线报告不声称自动保存到任务目录。

### 16.3 计算与费率

- AC-16：零退货、高退货、亏损、多件装结果符合公式口径。
- AC-17：仓储变化同时影响 S 和不可售退货分摊 D。
- AC-18：两季常规 FBA 配送相同，无仓储季节差价的站点结果相同。
- AC-19：售价、重量和尺寸跨档重新匹配；采购改变不使无关估计失效。
- AC-20：过期检查、来源变化、已知失效分别处理，未知费用不按零计算。
- AC-21：11 站点分别保留数据路径和常规/边界档验证，不仅凭美国案例宣称全覆盖。
- AC-22：AU 未取得关键退货处理费用时保持缺项；SA 第三方估计持续标注。
- AC-23：浏览器、服务端及保存报告使用同一公式，金额一致。
- AC-24：原 v1 回归继续通过，历史输入结果不被静默改变。

### 16.4 安全与性能

- AC-25：跨源、错误令牌、错误 Host、任意路径和费率改写请求被拒绝。
- AC-26：导出的 HTML 和 Skill 包不包含运行时会话令牌。
- AC-27：常规案例满足 1 秒/100ms 本地性能目标，网络时长单列。
- AC-28：Codex 实际打开填写页，不能仅证明外部浏览器可用。

### 16.5 已有验证记录

v2.1 最近一次实现验收记录：111 项 Node 测试通过，包含原有 94 项及 17 项本地 HTTP 服务测试。已在 Codex 内置浏览器验证空白经营输入到计算保存、刷新恢复、渠道增删、连续修改、无效输入和保存失败重试。

已有案例页面重算约 0.5–5.2ms，首载观察约 16.6ms；390px 宽度无横向溢出。上述是该次环境和样本的记录，不等于新环境、新费率变更无需重新验证。

## 18. 已知限制与后续候选

以下不是本版已交付能力，也不构成本次新增开发承诺：

- 澳洲额外退货处理规则仍需可靠来源补齐。
- 不同细分类目、危险品、超大件和特殊税率需要扩展规则及对照测试。
- 同一种渠道多个货代报价目前不能作为独立行并存。
- 修改规格文字不会重新采集另一 ASIN，切换商品仍需重新发起任务。
- 多页面冲突采用拒绝覆盖，尚不支持逐字段合并。
- 保存请求超时但服务端已提交时，重试可能出现版本冲突；以刷新恢复的已保存状态为准。
- 缺尺寸的商品仍依赖用户补填，无法保证所有链接零手工即可计算。
- 页面完成后没有自动聊天回调；有需要可后续增加明确授权的结果通知机制。
- 可评估批量商品对比、同渠道多报价及可视化敏感性分析，但不能挤占当前快速单品测算主流程。
