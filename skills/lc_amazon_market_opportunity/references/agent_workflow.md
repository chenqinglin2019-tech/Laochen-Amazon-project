# Agent Workflow Contract

本文件约束 Agent 的语义判断和留痕，不替代 CLI 的结构化计算。

## 站点、维度与打标

- 站点与 Listing 语言只继承项目 manifest；原始值和证据保留源语言，`display_values` 使用中文。
- 从 `03_dimension_candidates.json` 聚类消费者决策维度，去掉品类主词和无效词根；记录入选、剔除、补充维度和 LLM 调用摘要。入选维度通常为 3—6 个，并按搜索需求、产品区分、购买影响、可打标、业务可用性评估。
- 每个有效 Listing 一次性判断所有确认维度，先用标题、参数和类目文本；只有文本无法判断的维度才查看该 Listing 已有的图片或商品链接（使用时在 `evidence` 写明，未使用时在 `review_summary` 说明仅基于文本）。仍无法判断时填`不可识别`并留因，不要猜。查看已有 Listing 不属于“新增抓取”，但不得抓取新商品。
- 标签必须包含 `values`、`normalized_values`、`display_values` 和 `evidence`。只合并不改变消费者决策含义的高近义表达；`通用未限定`、`未披露充电`、`非候选安装位`等是明确不符合，而不是未知。
- 最终成员只按补标后的 `normalized_values` 匹配。不得重建清洗商品、新增抓取、调用飞鱼 API、执行 VOC 或产品开发。

## 需求定义与核心词

在 `prepare` 后读取 `niche_recommendation_workspace.json`；写完候选定义后先运行 `validate`，一次改完它列出的全部错误。逐行把商机记录标为`direct_need`、`brand_navigation`、`accessory`、`other_use`或`ambiguous`并说明原因。

- 候选必须说明谁、在什么条件下、完成什么任务，以及哪些必要条件改变购买选择。单属性、双属性或三属性均可。
- `exact` 行是需求证据；`partial`、父市场、附件和品牌导航只能作旁证。多个 exact 行按精确度、最后出现期数、近 90 天搜索量和行号确定主行，不能按高分选择。商机表数值不参与评分。
- 多维组合：按 `combo_review_template` 对每个组合审核一次。组合本身的标签条件由脚本给出；Agent 只判断它是否是买家能理解的需求（不是则 `drop` 并写原因），可改中文名，并从完整关键词表归属同时表达组合全部条件的 `direct` 词（如“紧凑 + 游戏”对应 small gaming desk）。找不到有搜索量的 direct 词时保留但只能作候补，不要硬凑。
- 使用 OR 表达替代方案，AND 表达必要条件；同义、父子或不可同时推荐的候选用双向`exclusive_with`声明。
- 关键词只需归属每个候选的 `direct` 词（完整满足需求边界），不要求对完整关键词表逐词穷举；`extended`／`ambiguous` 可选留痕。不得用泛词、附件词、品牌导航词或头部点击份额补足规模、竞价或成员。

## Top3 粗筛

补标、需求边界和 direct 词清单确认后运行 `shortlist`。粗筛直接选择最多 3 个不冲突市场：

- 四项分数（供需 80%、竞争 10%、新品 5%、规模 5%）全部由脚本按商品样本计算，Agent 不手算、不调权重；公式见契约 §4。
- 正式推荐需要：需求证据（exact 主行或有搜索量的 direct 词；组合只能靠 direct 词）、至少 10 个完整匹配有效 ASIN、有正月销量、稳健供需指数 ≥1.0、四项可计算。共享月销量占较小市场一半及以上的候选由脚本自动判为同一需求。

广告压力、关键词转化率、商机表均价、搜索增长和退货率不参与粗筛；后两项只展示风险。

Top20 从完整成员按有效月销量降序、同销量 ASIN 升序提取；不能反推成员或评分。报告中的复制按钮按顺序逐行复制 ASIN，不复制排名、标题或父 ASIN。

## 统一补表与进一步分析

粗筛后告知用户：提交每个冻结市场各 2 个 Excel（Top3 时共 6 个），每个市场 1 份细分市场关键词转化表及 1 份卖家精灵关键词表，文件顺序不限。两类表分工固定：关键词转化表（如 `关键词-20260905-….xlsx`）只取关键词、点击量和购买量，表内“最高出价／最低出价／建议出价”等出价列一律忽略；建议竞价只取自卖家精灵关键词反查表（如 `ExpandKeywords-US-<ASIN>-batch(20)-….xlsx`，以含 `Asin` 工作表识别）的 `PPC竞价` 列。每份转化表含统一近90天周期、关键词、点击量与购买量；每份卖家精灵表含关键词、`PPC竞价`、`流量占比`和 `Asin` 工作表（ASIN 与该市场冻结 Top20 完全一致，不足 20 个时按实际数量）。未收到全套文件时停留在`awaiting_keyword_conversion`；项目原有关键词表不能自动替代。

运行 `refine` 后，固定 Top3 身份、排名、四项分数、成员、Top20 和关键词边界必须与粗筛一致；价格或销量无效的商品只从八项结论样本中剔除并留痕。对每个市场独立：

- 先把卖家精灵 `Asin` 工作表与冻结 Top20 ASIN 完全匹配，以识别所属细分市场；再把关键词转化表与卖家精灵累计流量占比前90%关键词按精确标准化词重叠（至少80%）一对一配对。该关联不使用 `direct`／`extended`／`ambiguous` 语义。
- 只用同时有转化数据（点击量>0、购买量有效）和卖家精灵建议竞价（`PPC竞价`>0）的关键词：转化率为这些词的购买量之和／点击量之和，加权CPC为这些词的“词点击量／这些词点击量之和×词PPC竞价”累加；缺任一项的关键词整行忽略，不用其他来源（如关键词表推荐竞价）补齐。广告压力为加权CPC／（转化率×本市场完整有效商品算术均价）。保留匹配、排除和覆盖留痕；不设覆盖门槛，不按相关性过滤关键词。
- 使用本市场完整有效商品计算八项结论：评论依赖性、评分值依赖性、价格敏感度、最值得进入价格带、新品打造周期、商品垄断度、品牌垄断度、广告压力指数。
- 缺少覆盖、竞价、转化或商品字段时，只让对应广告项／结论显示无法判断；不得改变 Top3、借用其他市场数据或生成第三轮评分。

交接只使用同批 v10 粗筛及进一步分析回执，核对阶段、运行 ID、指纹、哈希、Top3 ID 与顺序。`08_niche_recommendations.json` 记录进一步分析，不是重新选择来源。
