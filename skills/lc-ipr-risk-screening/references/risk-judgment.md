# 风险判断规则（v2）

本文件是新任务的风险判断规范。判断顺序为：识别商品 → 发现候选 → 查看原始材料 → 比较共同点与关键差异 → 判断风险 → 单独判断置信度 → 写明补证及重新评级条件。

## 证据怎样决定等级

- 相似度、排名、供应商风险文字只用于发现和排序，不是侵权概率或最终等级。不能按分数直接判高，也不能因为供应商先判高而拒绝下调。
- `material` 表示需要保留并重点说明的候选，不等于高风险。中、低风险也可以保留 material 候选；七模块审阅必须逐条引用所有 material 候选。
- 外观设计以图纸呈现的整体视觉印象为主。实际查看目标商品图和候选图，比较轮廓、比例、构成、关键外形和装饰，说明共同点与关键差异分别怎样影响整体判断；不能只数相同或不同特征的数量。
- 瓣数、颜色、用途、功能不同并不是自动降级条件。说明其可见外形影响，并区分图纸中的主张部分和非主张部分。不能把主图未显示的底部、背面或打开状态写成“没有”。
- 对可能影响最终等级的重点外观候选，主动尝试取得完整专利图纸并实际查看。完整是该专利所披露的相关视图，不固定要求七张。记录成功查看的图号/页码；获取失败或仅有候选缩略图时如实记录尝试及缺口。
- 状态有效说明该权利仍需考虑，不自动说明目标商品落入其范围。Google Patents 或供应商状态只作为来源线索，不能写成已完成官方核验。

等级语义：

- 高：实际比较支持整体高度接近，已有差异不足以实质改变判断；必须说明证据和差异为何不足。重要视图缺失时仍可能高风险、低置信度。
- 中：存在实质相关性，应继续关注，但重要差异或尚未闭合的证据使现有材料不足以支持高风险。必须说明中风险的具体依据，不能仅因“资料少”默认判中。
- 低：在本轮范围内未发现明确风险信号，或有证据支持候选关联较弱；不等于没有权利或可以放心销售。
- 极低、极高沿用现有枚举，仅在有充分、具体理由时使用，不能作为空结果或高相似度的默认结果。
- 无法查看关键证据、无法进行基本比较：候选保持 `needs_review`，交付草稿和缺口，不编造正式等级。

## 风险与置信度分别表达

风险回答“现有证据显示什么风险”；置信度回答“证据能多充分地支持这个判断”。每个模块必须填写 `confidence_reason`。

- 目标只有主图，或候选仅有部分视图，且关键形态未确认：视觉判断的置信度为低；写清当前结论受什么限制。
- 有细节图不代表视图充分。必须判断侧面、底部、打开/关闭等相关状态是否实际覆盖。
- 状态未知、检索范围有限、来源失败主要形成置信度限制和待核实项，不能单独推成高风险，也不能单独证明低风险。
- 版权模块仍关注具体创意资产的来源链：相关来源或授权链不完整至少中风险；已确认相关资产未经许可使用至少高风险。不能因为外观差异大就同步降低版权风险。
- 综合风险取七模块最高值，综合置信度取最低值。v2 不启用 `compound_escalation` 额外加一级。

## 其他六模块

每个模块均按“证据 → 关联分析 → 风险理由 → 置信度理由”判断，不套用外观等级或外观比较方法。

- 实用/发明专利：比较技术特征及可取得的权利要求内容；外观不同不能排除技术重叠。
- 在审专利：说明申请内容与产品的关联及后续变化条件，申请状态本身不等于当前侵权。
- 文字商标：比较真实标识、文字近似及商品/服务关联。完整占位值 Generic 已由现有逻辑排除，不能计作商标命中；其他真实标识照常处理。
- 图形商标/商业外观：比较图形和整体识别特征，并结合商品/服务关联。
- 版权：比较具体图片、图案、角色、包装等创意表达及来源链，不能仅凭通用品类推定复制。
- 维权线索：说明案件/投诉与目标商品或相关权利的实际联系；发现案件不等于已确认目标侵权。

## 补充证据与审阅字段

先登记补充材料，再提交全批次候选处置。使用 `record-supplemental-evidence --task-dir <task-dir> --input <supplement.json>`，输入按 `contracts/supplemental-evidence-input.schema.json`：

- `schema_version`、`task_id`、`candidate_id` 绑定现有候选；`kind` 为 `patent_drawings`、`product_view` 或 `source_document`。
- `source` 填无凭据的 HTTPS 来源，用户提供的文件填 `user-provided`；`file` 为已有本地 PDF/图片，相对路径以输入 JSON 所在目录为基准。
- `description` 写材料内容及范围，`recorded_by` 写 type/id/session_id。返回的 `SUP-...` ID 用于审阅引用。
- 登记命令只复制并校验本地材料，不进行网络抓取，不代替实际看图；Agent 使用当前可用的浏览、下载、PDF和图像查看工具取得并查看材料。没有可用工具或获取失败时记录限制，不假装成功。
- 原始 PDF 与实际查看的渲染页可分别登记，并在描述中说明关系。只登记文件不能证明已经看过；必须实际调用查看能力，再填写查看范围。
- 文件、来源、摘要和候选绑定进入证据账本；补充证据不增加供应商查询完成数，也不伪造新的 provider item。

每条 material 视觉候选的 finding 除 `similarities`、`differences` 外，还必须有 `comparison`：

- `overall_impression`：整体判断，说明共同点与关键差异的权重及为什么对应当前等级。
- `target_coverage`：`limited` / `sufficient`；`candidate_coverage`：`limited` / `complete`。
- `drawing_review`：外观候选写图纸获取尝试、查看范围和结果；其他视觉候选写实际素材复核范围。
- `limitations`、`missing_evidence`：已知限制及待补材料，没有则显式 `[]`。任一视图覆盖为 limited 时必须非空，模块置信度必须 low。
- `reassessment_conditions`：后续什么证据会改变判断，至少一项；允许上调或下调。
- `supplemental_refs`：所用补充材料 ID，没有则 `[]`。外观图纸标为 complete 时，必须引用实际查看的 `patent_drawings` 材料。
- `viewed_assets`：每项包含 `role`（target/candidate）、任务内 `path`、`sha256`、`viewed_scope`（实际查看的角度/图号/页码）。必须同时绑定目标图和该候选材料，不能使用另一候选的文件。

审阅规则检查证据引用与文件完整性，不自动判断图像语义。Agent 必须真实查看，不得用供应商理由或模板填充这些字段。未进行官方核验时，沿用 finding 的 `official_status=not_applicable`、空 `verification_refs`，其含义是本轮未执行官方核验，不能解释为该权利不存在。

## 新证据和历史任务

新账本绑定 `risk_policy_version=2`；无该字段的历史账本按 v1 读取，不重写旧结果。已冻结但未终结的任务用 `revise-evidence` 开新证据版本，登记新材料后重新完成全批次处置、冻结、七模块审阅及发布校验；旧结论归档。completed/incomplete/failed 任务保持不可变，需要另建任务。

补充证据必须在当前版本的全批次处置前登记。已处置时先冻结并修订证据，不能绕过不可变记录。补充后的候选工作区绑定新摘要，不能提交补充前生成的旧批次。

## 复核示例（方法，不是固定答案）

发现阶段有高分的汉堡外观候选。补全图纸后，比较分瓣构成、容器形态、比例和目标实际可见结构；若重要差异使现有证据不足以支持高风险，可以保留候选并判中。目标侧面、底部、开合状态仍缺失时给低置信度，并写明“若补图显示整体更接近候选则上调；若确认差异成立则维持或下调”。不能固化成“汉堡都是中风险”或“只有主图最多中风险”。
