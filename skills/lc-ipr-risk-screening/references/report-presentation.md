# 报告排版与数据完整性

正式报告由 CLI 从冻结事实、证据账本和审阅记录生成。使用全宽响应式布局与内嵌图标，不依赖外部字体、脚本或图片服务。

## 固定顺序

1. 冻结商品事实：商品图片、标题、品牌、类目、市场与法域、ASIN、产品 ID、范围说明。
2. 筛查结论：风险与置信度、正式结论门禁、覆盖与重点候选、摘要、法律边界。
3. 查询与候选覆盖：必需、完成、未完成、候选数量、完成度和全部查询状态（含可选检索）。
4. 发布阻断项。
5. 七模块：外观设计、实用专利、申请中专利、文字商标、图形商标与商业外观、版权与创意资产、公开维权信号。
6. 风险细节：按上述模块顺序展示所有实际 finding、共同点、差异、图纸复核、证据限制、待补材料、重新评级条件、实际审阅文件与建议行动。
7. 完整证据备查：候选图片、完整图纸与补充文件、全部候选和处置、风险约束、完整结构化数据与摘要绑定。
8. 页尾任务信息与法律边界。

## 数据规则

- 不得用样稿、演示数据、虚构图片、推测数值或通用结论补足正式报告。数据缺失时明确标注缺失；未查询、待核对和无法判断不能改写为零命中或低风险。
- 页面仅调整展示顺序，不改写原始 JSON、证据摘要、判定和计费数据。所有候选均保留；搜索、筛选和分页只改变显示范围，导出完整数据不受筛选影响。
- 展示全部冻结商品图、账本中明确引用的候选缓存和审阅绑定材料；不扫描无关文件填充画廊。未保存的发现层图片保留缺失说明；已绑定审阅文件缺失、摘要不符、路径越界或报告过大时停止生成，不能静默截断。
- 图片与 PDF 原文件可离线保存；完整图纸不能用一张缩略图冒充。没有实际查看记录时不声称完成对图或全图纸审阅。
- HTML 内保留完整报告、商品事实、查询计划、查询覆盖和证据账本 JSON。原 JSON、CSV、Markdown 和 manifest 仍随任务保留；它们不能被视觉样稿替代。
- 已完成的正式报告继续使用原 manifest，不因升级排版而覆盖、重写或重新请求供应商。新任务或正常证据修订产生的新报告使用新版展示。
