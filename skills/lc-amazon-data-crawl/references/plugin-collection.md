# 店铺与关键词：卖家精灵面板采集

本流程适用于 `storefront`、`keyword_search`。通过日常 Chrome 的 OpenCLI Browser Bridge 操作卖家精灵公开 DOM，点击“加载更多”，最后使用普通“导出”。不启动 Chrome for Testing，不调用系统鼠标，不切换窗口或标签，不读取 Vue/插件内部变量或私有接口。类目榜单、图片竞品仍走原流程。

## 配置与数量

复制 `assets/config/amazon_front_storefront.json` 或 `amazon_front_keyword_search.json`；runner 内路径为 `config/`。每个新任务使用新 `job_id`。

- `entry_mode: "current_tab"`：接续用户事先选好的店铺/搜索页面；可用 `start_url` 约束来源。无需输入文件。
- `entry_mode: "batch"`：读取 `store_urls_file` 或 `keywords_file`，在同一绑定标签内串行导航。店铺 CSV 列为 `store_url`、可选 `store_name`；关键词列为 `keyword` / `关键词` / `search_term`。
- `store_max_records`：每个店铺默认 **1008**。
- `keyword_max_records`：每个关键词默认 **2000**。
- 用户指定正整数覆盖对应默认值；明确要求全部才设为 `"all"`。不接受零、负数、null 或字符串数字。
- `marketplace_domain`：批量关键词站点，默认 `amazon.com`。店铺使用输入 URL 的站点。
- `store_sort_orders` / `keyword_sort_orders`：见 configuration.md 的排序名称。同一站点、同一来源的排序共享数量预算，切换排序、重试和恢复不清零。
- `product_filters`、`include_sponsored`：导出后本地筛选；默认不排除广告、不开启业务筛选。筛选需要的字段缺失/无法识别会报错，不将未知值视为符合条件。

上限按插件“加载数据 N 条”计算。最后一批可以自然超出；原始文件保留全部实际导出行，正式结果按原生导出顺序先截取上限，再按站点 + ASIN 去重，最后筛选。去重或筛选后不足目标，不补抓。已有页面达到上限则直接导出。插件提前结束则交付已有数据。

`limit_reached` 表示达到用户指定数量；`source_exhausted` 表示插件已结束。两者都不保证覆盖 Amazon 店铺/关键词的所有商品。插件序号单独保存，不作为 Amazon 搜索排名。

店铺商品页的 Amazon 主搜索区出现明确“无搜索结果”（例如 `No results for your search query`），且连续稳定 10 秒、没有实际搜索商品时，按店铺消失或暂无可售商品直接跳过，继续下一店铺。仅凭插件空白、计数未知、加载超时、推荐商品区域或验证码不能跳过；风险与登录检查仍优先。跳过前不初始化筛选、不点击加载或导出；已有中间导出保留，断点写入终态 `store_no_results` 和 `skipped_items`，同一 job_id 恢复不重试。全部目标处理后有跳过则返回 `completed_with_skips`。

## 操作与节流

先通过 `scripts/check_auth.sh`（Windows 用 `check_auth.ps1`）。用户在日常 Chrome 安装 OpenCLI Browser Bridge、卖家精灵并登录插件，选好一个 Amazon 工作标签。首次绑定后可以切到其他标签或应用；工作标签须保持打开，不手动改网址、筛选、排序或刷新。

运行 `amazon-front-dry-run --config ...` 检查配置，再运行 `amazon-front-run --config ...`。`sellersprite-check --config ...` 只检查已绑定页面与面板状态。建议后台启动并写日志，跟踪 `run_heartbeat.json`。macOS/Linux 可用 Python `subprocess.Popen(..., start_new_session=True)`；Windows 用 `Start-Process`。不要重复启动任务。

- 单任务、单工作标签，每轮只点击一次“加载更多”。前一轮结束、计数与可见字段稳定 10 秒、操作间隔到期、休息结束，才允许下一次点击。
- supervised：远程动作随机间隔 20–30 秒；每 20 次休息 1–1.5 分钟；每 100 次改为休息 2–3 分钟，不叠加短休息。
- unattended：45–75 秒间隔；每 10 次休息 2–3 分钟，不另设百次长休息。
- 导航、打开会触发查询的插件面板、加载、重试、导出均经过全局持久化调度。跨来源、跨 runner、跨重启保留计数与休息期限。DOM 状态每 2 秒读取一次，不刷新或查询。
- 店铺每轮最多等待 180 秒，容纳后台标签的插件延迟。加载无进展时 supervised 60 秒后复查并最多重试一次；unattended 依次 120、300 秒复查。仍在加载时绝不重点击。关键词的正常观察同样为 180 秒，只有异常加载按下节延长并确认结果。
- 同一目标自上次成功导出累计 100 次成功加载才中间导出；恰好结束则只做最终导出。普通任务默认结束时导出一次。
- 全局两次导出至少间隔 60 秒。下载未确认前不再点击；明确失败最多重试一次；未知结果保留待确认状态。恢复同一目标先寻找原下载，找到并验证后提交，禁止直接重下。
- 验证码、限流、权限、额度异常停止新增操作，保留全局风险暂停和原退出码。明确验证码（captcha_or_robot_check）在两种模式下都先保存断点、退出并默认暂停 24 小时；用户明确确认本次验证码已通过后，可立即用原命令加 --resume-after-review 提前复核恢复，不需等待 24 小时。未经确认不恢复，复核仍出现验证码则再次停止。其他限流、访问拒绝和账号限制仍遵守原暂停期限，不能凭验证码确认提前恢复。上述间隔是本地策略，不是平台公布的安全额度。

## DOM 和导出

### 仅关键词加载恢复

`keyword_search` 使用 `scripts/keyword_load_recovery.py`，店铺不进入此分支。正常条数增长后仍只需稳定 10 秒，DOM 仍每 2 秒检查；正常读取/点击次数与原流程相同，无额外 30 秒结束复核。达到数量上限、已确认增长后正常结束，或首次接管没有待确认操作的已加载页面，继续原导出流程。

- 一次实际发出的加载先观察 180 秒；仍在加载或结果未知时，只读观察延长至累计 600 秒有效时间。点击后条数不增，即使按钮消失也不能当作完成。增长且稳定即可接续，不等满期限。尚未发起加载的初始准备保持原 180 秒规则。
- 仅本轮新出现、位于产品面板的明确“加载失败，请重试”类提示，且页面加载尝试标记与断点一致，才算失败证据；旧提示不算。界面未暴露可信失败证据时保留未知，不从超时/无增长推断失败。按钮在点击前已变化时由同一次 DOM 检查返回“未点击”。
- 明确失败或确认未点击、且页面未加载、条数未变、按钮可用时，沿用 supervised 60 秒一次、unattended 120/300 秒两次冷却。每次重试仍经过全局节流/休息；次数不增加。冷却后同一次 DOM 操作再次核对计数及状态，迟到数据已经增加就取消点击。新重试拥有独立观察预算。
- `current_task.keyword_load` 保存基准条数、页面身份、尝试标记、已用观察时间、重试次数和冷却期限；原 `load_pending` 保留。恢复先处理旧加载，未确认的点击不重放；只在确认增长后增加成功加载次数。旧的 `load_pending` 断点首次恢复按未知结果建立观察记录，不更换 job_id；已完成任务不重采。
- 等待时间提前落盘；进程恢复不重置观察和重试预算。OpenCLI 只读恢复时间不计入加载观察，恢复后连续稳定计时重新开始。600 秒用完后重跑仅允许读取和确认已经到达的结果，不再获得新的完整观察窗口。
- 到期仍未知返回 `retry_later`（20），当前来源保持未完成，不跳过、不写零、不自动刷新。已提交原生文件与待确认下载台账保持原规则；页面计数是观察值，不能当作已下载记录。验证码、登录、限流、标签/文档变化始终优先处理。

新增 DOM 观察字段只在关键词请求下返回；店铺继续使用原 `busy` 等字段，不改变原有完成与重试行为。错误文本不写入断点，仅保存比对摘要。离线验证需覆盖正常时钟/调用次数、店铺基线、慢加载、回包丢失、旧断点、跨进程预算、迟到数据、风险与导出保护；真实关键词验收单独报告，不能以模拟测试代替。

### 原生面板操作

所有操作定位于 `#seller-sprite-extension-app` 的产品查询容器。下拉菜单若传送到容器外，必须能通过插件的 scoped DOM 属性及弹层归属确认；隐藏过渡弹层不能参与匹配。控件存在多个匹配就停止。

准备阶段重置过滤、恢复产品视图/展示全部、开启所有商品标识、关闭列表 ASIN 去重、清空勾选并启用数据列。导出选项关闭额外翻译和高清图片请求。点击普通“导出”，不用“导出明细”。表格存在虚拟滚动，当前 DOM 行仅作下载样本验证，不能冒充完整数据集。

使用下载 ID、发起时间、文件名、Amazon blob 来源、文件完成状态和实际表格内容联合核验。主表须唯一，文件行数须与面板数量一致，并包含面板抽样商品。异常文件保留，不提交数据检查点。其他标签同名导出无法可靠区分时应停止核验，不能猜测接受。

价格、销售额、FBA 列按精确列名及货币后缀映射；父销量、子销量、评分值、评分数分别保存。未知列保留原 XLSX 和原始行。导出提示的“2000 条上限”不能视为已验证事实；实际文件若截断或数量无法解释，报告部分完成。

## 输出与恢复

`outputs/<job_id>/` 中保留：

- `raw_exports/`：原生 XLSX 和对应核验报告，包含实际导出数量，不截断原文件。
- `records.jsonl`：按预算截取后的来源记录。
- `dedup_total.xlsx`：按原生下载表格式合并的去重、筛选结果，完整保留所有列、图片和格式；不改列名、不新增“采集范围”等替代工作表。
- `quality_report.json` / `run_summary.json`：插件数量、导出数量、截取数量、唯一 ASIN 数、筛选后数量、停止原因、原始文件、异常和 `partial`。
- `state.json` / `run_heartbeat.json`：任务、标签 ID、来源预算、当前加载进度与持久化快照。

重新执行同一命令会接续身份一致的工作页。工作标签关闭或连接丢失就停止，不创建或接管别的标签。用户选好替代页后显式传 `--rebind`，重新采集未完成目标，用新快照替换旧快照，不能累加同一目标的多次累计导出。工作页被改到其他网址时同样停止。

### 原生格式合并

- 以经过核验且断点已提交的原始 XLSX 为唯一单元格和图片来源。只读取 `state.json` 中各任务的 `raw_file`，不得扫描整个 `raw_exports/` 混入中间导出、失败下载或旧快照。新记录保存原文件、工作表和 Excel 行号；旧断点通过来源、排序、ASIN 和完整原始行唯一定位，无法唯一定位就停止。
- 数量截取、站点 + ASIN 去重、业务筛选顺序不变，保留首次出现的完整原始商品行和对应图片，不拼凑多条快照的单元格。保持任务输入顺序和各来源原生排序；不把新品榜改成全局 ASIN 排序。全部原始字段均保留，包括未知字段；不增删、改名或重排列。
- 直接迁移 XLSX 原始单元格、样式资源、共享字符串、图片及链接关系，仅修改必要的行坐标和内部引用。保留颜色、字体、边框、对齐、数字格式、列宽、行高、冻结、页面布局和原工作表顺序；图片字节不重新压缩、图片位置随所属商品行迁移。不能用 JSON、CSV 或普通 `Workbook.append` 重建成品。
- `Brands`、`Sellers` 按来源追加原生统计行，保留下载时的统计口径，不冒充筛选后的重算统计；相同 `Note` 仅保留一份。来源审计、计数、筛选原因和原文件路径写入 `records.jsonl` / `quality_report.json`，不改变原工作簿布局。
- 列、工作表或布局不兼容，或出现尚未支持无损迁移的合并单元格、公式、图表等对象时，明确报错并保留原文件、断点和已有成品；不得丢弃对象、删列、清空图片或降级到简化表。扩展兼容性并验证后再输出。
- 写入临时文件并校验 XLSX 内部关系及压缩包后，原子替换正式结果。验证完整字段和值、单元格样式、列宽行高、图片字节及锚点、链接、冻结和行数；图片原本缺失的商品不编造图片。

旧任务重建或多任务合并：在 runner 内使用当前 Python 环境运行 `scripts/merge_plugin_outputs.py --job-dir outputs/A --job-dir outputs/B --output-dir outputs/merged`。可重复 `--job-dir`，顺序即合并顺序；有筛选要求时加 `--config config/x.json`，省略则不过滤且不排除广告。此命令通过云端鉴权后仅做本地合并，不打开浏览器、不重新下载、不改采集断点。

下载待确认：先运行 `plugin-export-review` 查看状态；仅在确实检查了 Chrome 下载、没有进行中下载或另存为提示后，才运行 `plugin-export-review --confirm-no-active-download`。这只清理待确认标记，保留节流时间与已消费下载 ID；优先用原命令自动接续已完成的同目标下载。

旧 `max_pages_per_keyword`、`store_page_limit`、CDP 浏览器配置不能直接使用；删除旧分页字段，选择新模板与新 `job_id`。旧断点与新 schema 不兼容，不自动将页数换算为加载次数。更新 runner 会保留用户配置，所以旧配置需明确迁移。`amazon_front_public_quickstart.json` 也改用插件，已不提供无插件关键词采集入口。

## 验证范围

离线测试使用模拟时钟、原生格式 XLSX 样本及 DOM 控件测试，不启动测试浏览器。真实环境验证应使用绑定的日常 Chrome 后台页；分别核对店铺、关键词、超过 1000/2000 条文件及焦点保持。合成 2100 行样本只证明解析/截取逻辑，不能替代插件真实导出上限验证。

## 原标签读取自动恢复

暂态的标签列表、面板快照和下载状态读取失败使用 [共享只读恢复](opencli-read-recovery.md)：2、2、30、60、120 秒，之后每 300 秒；连续故障累计最多 30 分钟，期限跨重启保留。恢复等待不消耗插件观察预算（店铺 180 秒，关键词异常加载 600 秒）、下载 120 秒和导航／注入观察预算，页面恢复后重新要求连续稳定 10 秒。店铺加载重试、全局操作计数和休息规则不变；关键词按上述独立恢复规则执行。

连接故障到期直接保留当前来源并返回 20，不进入“加载无进展”点击重试。`load_pending`、累计条数、原生导出 pending 台账和已确认下载保留；恢复后核对原页面或原下载，不因读取失败重复加载或导出。首次绑定先保存会话／标签，连接复核失败不再一律改写成人工重新绑定提示。
