# 声明级二次分流宿主（默认关闭）

> r5d4 起的新任务用 `prereview_screen.py`（终审前筛查）代替本宿主：它在本宿主的逐字核对规则上，再要求已记录的逐要素比对给出同样结论，两次判断一致才排除，见 [一键流水线](pipeline.md) 的“终审前筛查”。本宿主仍默认关闭，下文的校准流程不变。

`scripts/claims_triage_host.py`：候选在摘要或结果卡层面被入选后，若其独立权利要求已经取得，由一个原生文本会话判断**每一项独立权利要求是否都要求产品对象不具备的必要特征**。

## 它只能做的一件事

- 唯一能产生的变化是把当前 `selected` 的专利／实用新型候选下调为 `not_selected`（阅读层级 `independent_claims`）。不上调、不新增候选，不判断有效性、法律状态或风险。
- 下调必须：覆盖该候选**全部**独立权利要求；每项独立权利要求至少给出一条逐字摘录（≥12 个字符）；程序逐条核对摘录确在已留存的权利要求原文里，不在则**整份输出作废**，任何一项不确定一律保持入选。
- 独立权利要求按“不引用其他权利要求”解析；任一独立权利要求超过 6000 字符时该候选不进入本宿主，不截断后判断。
- 通过现有“变更重开”事务写账：先 `record_reopen`（保留原入选的历史记录与证据），再用普通记录器追加新决定（记录者 `native-claims-<会话>`），再逐条 `record_reopen_review`。任何一步失败都不会静默改变旧决定。

## 启用与校准

1. 默认关闭：新任务不带 `claims_triage_revision`；`claims_triage_host.py` 在没有该标记时拒绝正常运行。
2. 在**已完成**的任务（含已有 `independent_claims` 阅读层级的人工决定）上运行：

```bash
python -X utf8 scripts/claims_triage_host.py --task-dir /absolute/run --calibrate
```

   `--calibrate` 照常启动原生会话，但**不写任何账**；逐个候选把宿主的提议与账里已有的人工决定比较，写入 `claims-triage-calibration/calibration.json`。分类：一致；保守分歧（宿主保留入选而人工已排除，安全）；**不安全分歧**（宿主排除而人工保持入选）。`verdict`：
   - `failed_unsafe`：有任何不安全分歧，退出码 1；
   - `inconclusive_no_positive_control`：没有不安全分歧，但被比较的候选里**没有一个人工保持入选的对照**——此时“零不安全分歧”是空洞的（没有任何可能被错误排除的反例），退出码 1，不得据此启用；
   - `passed`：零不安全分歧，且至少一个人工保持入选的候选被宿主同样保持，退出码 0。
   只含“人工排除”决定的任务（例如全部 8 个已读权利要求的候选都被降级）只能衡量宿主能复现多少次排除，不能证明安全；需要一个含对照的任务，或把多个任务的校准结果合起来判断。校准不会写账，但会占用 host-triage 分析额度并在任务目录写 `claims-triage-calibration/` 与计时日志；请在你愿意写入这些文件的任务目录上运行。
3. 校准通过且任务所有者确认后，新任务创建时加 `--claims-triage-host` 才启用；然后 `python -X utf8 scripts/claims_triage_host.py --task-dir /absolute/run` 处理当前全部满足条件的入选候选。

宿主占用独立的 host-triage 分析额度（与来源、终审额度分开），失败或无效的批次保留原入选，不登记任何排除。
