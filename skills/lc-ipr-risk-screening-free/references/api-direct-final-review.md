# API 直接采信与一次最终双审

适用于新任务的 `retrieval_workflow_revision=api-first-v3`、`review_policy_revision=final-double-review-v1`。本契约优先于其他参考文档中历史 v1/v2 的“必须官方网页”“商业 API 仅作发现”及“09C 阶段双审前置”规定。旧任务保留冻结版本，不自动补标记或迁移。

新任务另用 `assessment_revision=known-findings-risk-v1` 与 `presentation_policy_revision=operator-report-v1`。运营等级只取已查明适用当前风险；无完成复核的适用判断时风险待定、暂缓上架，并分别披露实际已查步骤、未完成步骤及待判断候选。查询进度和原始未知不作为评级门槛；原 `risk:null/pending` 候选不伪装为已核实，详见[新风险策略](risk-estimate-rules.md#新任务与显式重评known-findings-risk-v1)。旧报告按原策略保留，显式重评建立新版本。

同一已读准确原件为报告制作的 PDF 展示副本和受控页，可标记 `evidence_use=presentation_only`，并以 `presentation_source_evidence_id` 绑定既有原件。新运营策略仅在准确公开案号、地域、类型、原件哈希及 PDF 字节数匹配时，将这些附件排除于自动分流事实摘要；图片和原件仍执行完整性校验、进入最终审阅和交付包。若附件明确成为候选事实引用，或原件身份、字节及用途变化，仍触发对应判断复核。未绑定或仅自称展示用途的附件不享受此规则，历史策略保持原语义。

## 来源与补证

- 所有支持国家采用“国家 × 权利 × 所需信息”路由。已配置、获准使用且实际响应符合契约的 API，其原始字段可直接支持调查、比较、状态判断及报告。API 支持的事实不再增加 USPTO、TSDR 或其他登记网页的重复核验。
- 专利使用 OPS、Serper Patents、SerpApi Patents/详情；美国外观保留 `country=US/type=DESIGN`。OPS 不承担其没有覆盖的美国权利要求全文。Signa 负责商标文字、公开类型筛选、详情和标样；EUIPO、INPI、JPO 依目标地域与实际已获权限使用。内测图片相似接口不默认启用。
- 版权、商业外观、未注册外观、图形商标和维权信号按需使用 Serper Search/Images 及 Lens；公开网页或图片匹配本身不携带登记权利状态断言。注册与非注册事实按其实际内容进入同一既有证据台账。
- 第一次真实业务响应兼作具体操作验收。复用对应凭据指纹、接口、国家、权利、权限和操作的验收；接口或凭据变化、权限变化、实际响应异常时再检查。API Key 存在不等于获得调用授权；原鉴权、余额、购买及充值限制不变。
- 补查顺序固定为已有材料、同来源缺失内容、能解决具体缺口的其他 API、必要官方网页。网页回退必须绑定具体候选或查询范围、缺失字段或冲突及判断影响；不得只为“再次确认”请求第二来源。
- 沿用现有查询、重试与发现目的上限。已取得但未读材料先处理，未知提交先查回执。没有可执行补证时记录真实限制和恢复条件，完成本轮报告，不循环换词或重复提交。

## 事实采信与复用

`trusted_api_record` 保存在既有 evidence entry 中，绑定提供方、实际数据上游、准确记录身份、原始文件及响应哈希、字段出处、查询时间和可得的来源更新时间。`trusted_api.accepted_candidate_facts` 与 `accepted_verification` 是覆盖、专项、评级和发布共用的采信结果。

- 只采用实际返回的完整字段；申请人不等同当前权利人，历史授权事件不等同当前有效，别国或别个同族成员不能代替目标记录。错误号码、跨国状态、冲突、截断、失败和空结果不形成已核实事实。
- API 原文、图样和状态可以满足相应义务，不要求再盖“官方网页核验”标记。只有摘要或缩略图时，按具体比较需要补全文或必要视图。不因使用第三方 API 统一降低置信度。
- 相同请求及已留存的原文和图片复用，保持原始回执；Serper Patents 与 SerpApi Patents 同属 Google Patents 上游，不能计成独立交叉验证。共享读取可支持多个适用义务，各国法律适用仍分别判断。
- 动态事实默认复用 48 小时，静态文件复用以内容哈希为准。最终冻结保存 `task.final_review_freeze` 的固定评估时点和事实语义指纹；事实未变时审阅持续时间不会启动重复查询。新增事实或原有内容实质改变时重新准备并冻结。

### 公开作品与未注册权利材料

公开 API 材料也使用 `source_form=trusted_api_record`。其 `document_id` 或 `api_record_identity` 必须精确匹配规范候选的 `url`、`source_url`、`image_url` 等公开 URL；系统生成 `api_candidate_identity`，调用者不能自行指定。材料回执自动记录 `api_public_content_scope`：

- `public_identity`：公开对象的准确身份；`source_excerpt`：实际返回的标题或摘要。
- `original_content`：未截断的 `full_text`／`document_text`，或明确 `content_complete=true` 的 `text`／`content`，或通过本地文件哈希校验的非缩略原图。
- `disclosure`：已有原始内容且实际返回 `publication_date`、`published_at` 或 `disclosure_date`。不得从检索时间推造首次公开日期。

M07 `public_facts` 若仅引用 API 材料，supported 事实须将 `api_fact` 明确设为上述实际满足的类型。版权的原作品比较要求 `original_content`；摘要不可当作完整作品。

M06 未注册外观的身份和保护内容可使用准确 API 公开身份、原文和图样。`legal_conditions` 还须同时引用已读且充分的 `legal_rule` 材料与公开材料，按原有 `rules_basis`／`conditions` 记录披露内容、日期和地域。推导状态、地域效力或权利人时，须绑定同一范围最新且全部条件受支持的 `legal_conditions_event_id`，填写 `inference_reasoning`，并以作品规范 URL 作为 `right_identity`；材料及证据引用必须保留规则和公开资料。系统标记 `analysis_basis=public_facts_with_applicable_rule`，不会把该法律分析写成登记状态；未知条件继续保留未知。

## 最终审阅与交付

保留 09A 进度及 09B 事实分析，关闭 09C 阶段双审前置。完成可执行调查、材料处理、分流与比较后，先运行 `review_readiness.py`，再用 `report_review_host.py` 对同一冻结输入执行两位隔离审阅者。第二位不读取第一位当轮结论。

新任务的实际执行使用 `module-double-review-v1`：两条独立链各分技术、外观、表达三模块并行阅读同一冻结版本的准确原文和图样，随后各自汇总一次总体、范围和限制。默认四个原生并发槽，六个模块加两个汇总共八个真实会话。各单元绑定实际模块的 session 及原始日志；汇总不改写模块判断，不能把多会话来源合并伪装成一个原审签名。准备、冻结和登记复用同一个内容绑定的进程内准备上下文；原件或语义变化仍拒绝继续。具体命令、隔离与输出结构见[最终双审宿主](report-review-host.md)。

每份审阅均须提供 `final_review_statement`，其 `overall`、`scope`、`limitations` 为本轮实际判断文字。记录器保存 `review_context.final_review.unit_bindings`、执行摘要和原审引用；验证通过后 `assessment.final_review` 是业务完成和 HTML 审阅状态的共同来源。没有 09C 批次不会使最终报告再显示“待阶段双审”。

进度文字、日志、生成时间、查询队列排列及同内容哈希文件的本地路径变化不重开审阅；权利要求、图样等证据内部顺序仍属于判断输入。真实产品、适用范围、查询语义或证据变化会重开受影响判断与总体影响。新一轮使用以下可选参数：

```bash
python scripts/report_review_host.py --task-dir TASK --output-dir NEW_REVIEW_DIR \
  --previous-first-review PREVIOUS_FIRST.json --previous-second-review PREVIOUS_SECOND.json
```

宿主仅将各审阅位自己的旧审阅及可复用单元交给该位。Agent 用 `reused_unit_ids` 明确引用未变化单元，只输出变化／新增判断；总体、检索范围、未解决问题及信号数组按本轮输入重审。手工单独录入 `record_independent_review.py --previous-review OWN_PREVIOUS.json` 仅适用于历史任务；新任务缺宿主生成的 `module_execution` 会被拒绝，须经 `report_review_host.py`。旧审阅完整保留其原输入摘要与执行记录，不能将旧签名改绑新摘要，也不能让两边复用同一个原审阅来源。

评级或运营展示策略变化属于本轮实质审阅输入。原事实、图样及比较材料可直接复用，不重新查询；含原评级政策的判断单元必须形成新审阅，不能仅修改其等级或签名。新总体与模块运营等级共同读取 `known_findings`；候选的原始待判断结论仍在专业附录保留，不能因为运营显示低风险而计成事实查清。

有证据的具体风险及置信度正常报告，缺失信息单列。全部必要事实和工作完成才标记 `business_complete`；只剩有据且有界的外部限制时，可在最终双审后标记 `limited_round_closed` 并交付带限制 HTML。文件送达验收仍使用既有发布与实际入口流程。

### 无法取得全文或完整视图

API 字段补查已耗尽时，先在 M06/M07 记录相应 unknown 事实、读取现有部分、完成批次及 limited 补查审阅。若完整保护内容或必要视图确实无法取得，可在 gap 中声明 `unavailable_comparison`，包含 `required_facts`、具体 `reasoning` 和 `readable_parts_review`；M06 已完成但仍未知的比较另列 `unit_ids`，并在相应义务绑定中引用当前比较及 `protection_fact_event_id`。

只有准确字段证明和当前未知事实匹配，且没有可用于建立完整清单／比较的已读完整材料时，才把相应 inventory 或商标比较待办投影为受限。已有完整材料、可执行单元比较、未读材料、冲突及未审变化继续阻断结束。受限不等于免做、正常完成或具体排除事实；运营风险等级由 `known-findings-risk-v1` 独立计算，来源恢复或新材料到达后按原待办重开。

### 已读准确 API 请求与缺字段分开结束

在 `api-first-v3` 中，已成功返回且通过原始回执、当前计划和整记录阅读绑定的 `candidate_detail`，如果其剩余字段已完成 M06/M07 的有据受限审阅，可以结束这个原请求的 09A 工作。只消除同一查询和范围内重复生成的 `NECESSARY_ACTION_PENDING` 及派生 `SPECIALTY_SOURCE_PENDING`；`API_RECORD_FACT_GAP`、未知事实、等待用户资料、未读材料、恢复动作及其他查询保持原状态。原请求完成不代表缺失字段已查清，也不证明当前权属或低风险。

### 有界公开排名范围结束

`api-first-v3` 加 `public-discovery-v1` 的 Lens 公开主图排名，可以在当前准确查询、原响应及原操作验收、整批实际材料处理、当前轻分流和公开身份有界调查均有效，且正式补查审阅为 `stop_bounded_discovery`、当前语义复核明确未全覆盖时，投影为 `BOUNDED_PUBLIC_DISCOVERY_SCOPE_LIMITED`。此规则只接受已保留的总量未知排名回执和冻结的一页范围；复用查询引用原真实请求的验收，不创建新的实际提交。

该限制不声称分页能力缺失、登记全集已查清或权属已确定；未访问排名范围、作者／首发／授权链未知继续列明。具体候选补图、未读原件、未处理卡片、可执行补查及其他权利的完整检索仍分别阻断结束。新公开来源或影响判断的外部材料到达时复核受影响范围。

历史非阻断的预算保留／表达计划标记，在同意图、国家、权利、维度、来源路径及冻结表达已有准确查询时，不再生成无查询的重复计划工作；预算与调用授权仍使用原规则。精确撤销且从未取得响应的查询不重新要求提交前语义审阅；已取得材料、逻辑复用和未知提交继续保留处理义务。

同一有界公开端点规则也支持美国 `SerpApi google_patents` 的专用 `type=DESIGN` 搜索：必须原始响应 `search_parameters` 准确绑定 `google_patents`、US、DESIGN、原查询及冻结 `num=max_candidates`，实际全部返回记录经过阅读与当前轻分流，原验收、stop 审阅和 after 复核均有效。仅接受 `bounded_discovery_total_unknown`，不把未知总量当全集清空；普通专利、其他地域、错误筛选、失败、未审材料及额外已规划页均不能借此结束。

OPS 原冻结一页范围也可使用有据 scope 限制：仅 `search` 的 `page_limit`、明确 `range_verified`、原计划和实际请求范围一致、真实区间数／返回数／总量一致时适用。必须完成全部实收材料与当前轻分流、原签名操作验收及明确未全覆盖的 after／stop 审阅；报告列真实返回数、声明总数与未访问数，并保留分页能力有效。未审材料、可执行新页、已规划细化查询及具体候选补证各有自己的处理义务，不因原范围限制而删除；原计划已冻结一页时不为重复核验无限追加页。

### 候选补证预算与原审阅复用

- SerpApi 专利/Lens 共用原有调用上限，真实网络尝试照原消耗计数；已提交失败与未知提交不退额。预算预留仅按物理请求计数：原始文件和记录绑定完整的 Lens 逻辑复用不另占槽，同 wire、同地域且在 48 小时窗口内的可用原回执允许待执行逻辑请求复用；缺原件、错参数或未知提交仍预留。
- 只有已有 hash 绑定取消且从未产生 run 的查询可以撤回预留；不删历史计划。缺字段补查先检查已尝试操作，再检查全任务预算；已耗尽字段调查的原预算备注仅作为历史审计材料保留，当前事实、证据和缺字段变化仍使原凭据失效。
- api-first-v3 的 `generate_search_plan.py --expand` 持久化新候选补证动作，并返回真正写入的计划。旧版本继续原分流行为，展开不授权请求或宣称事实完成。

- 美国 Serper 网页维权线索使用同一有限公开范围门禁：准确请求、原接口验收、全部实收处理、当前分流和停止审阅均通过，才结束原冻结一页范围；未知总量和维权主体/事实未知继续披露。
- OPS 原表达真实零结果可绑定同一国家、权利、情景及完整当前产品方向的已审 native 范围结束凭据，复用本轮调查而非替代原检索结果。必须原零结果 XML 完整性、精确合法回执、04A、原操作及当前停止审阅通过；共享查询必须原件完整、全部实收处理且当前有界审阅有效。不会声明并不存在的父子关系，不会把未访问记录/未知事实计成已查清，也不关闭其它页或候选补证。

- 未定位地域的 `needs_info` 卡片，仅当前已读决定的全部动作均为有真实登记证据与完整 05B 前提的 `user_information` 时，按这些动作投影用户等待；原地域、类型、身份缺口与恢复条件保留。混有公开来源动作、未读内容、未知证据或失效决定仍待处理。
- 准确候选请求的失败材料只归其 hash 绑定请求的候选与情景；失败本身仍需本轮材料去向和补查审阅，不扩成全地域所有候选的潜在新资料。严格已读整记录及已审字段限制不会因 09A 请求已完成而重新生成提交待办；合法未提交取消不生成提交义务。
