# 来源操作验收、选路与范围取消（03C）

新任务默认使用 `api-first-v3` 与 `final-double-review-v1`，以[API 直接采信与一次最终双审](api-direct-final-review.md)为优先契约。已采信 API 字段不生成官方网页重复核验；过程保留事实分析，取消 09C 阶段双审前置。下文旧修订仅约束保留该版本的历史任务。

API-first-v3 新任务冻结 `source_operation_revision=source-operation-v2`，按文末的业务请求验收规则处理；保留 v1 的历史任务按下述人工操作审阅合同解释。能力须按来源、国家、权利类型、具体操作、编译器和检索维度判断；一次成功响应只说明有回执，不说明字段生效、分页可靠或整站可自动执行。

接入维护方在实际来源材料审阅通过后，可用 `source_operation_registry.py --task-dir DIR --review-id ID --maintainer NAME --acceptance-reason TEXT --input-mode TEXT --limitations TEXT --adapter-version VERSION --state automatic` 将具体操作追加到 `source-operation-registry.json`。登记保留支持范围、输入方式、限制、维护方、核对时间、适配器版本及审阅摘要；此发行包登记为空，不预置真实来源的已验收结论。新任务预检把登记快照写入自身 `source-capabilities.json`；恢复时必须与包内维护记录逐项匹配，不能靠编辑任务快照伪造验收。后续任务复用已验收操作，不逐商品重复验收；运行异常仍可在该任务中审阅并形成待修复工作。维护方也可用已审异常追加 `--state unvalidated` 或 `unavailable`；同一精确操作取最新登记，旧条目仍留存。已有任务若需采用新登记，先明确刷新能力快照，并按现有计划修复入口追加受影响查询的重新绑定；变化只影响匹配操作，已得证据与计数不重置。

实际执行后，用 `record_source_operation.py --task-dir DIR --input REVIEW.json` 追加操作审阅。输入必须给 `provider`、`query_id`、`source_run_id`、`reviewer`、`reason`、`decision`，以及 `checks` 下的 `request_response_binding=true`、`field_effect`、`pagination`、`known_number`、`original_content`、`current_status`。各检查用 `verified`、`not_applicable`、`single_page`、`failed` 或 `unknown`；仅确证具体操作所需字段、分页及号码／原文／动态状态时可选 `accepted`。字段被静默忽略、分页重复、响应无法绑定实际请求时选 `rejected` 或 `unvalidated`，记具体原因并继续该操作的能力缺口；不得把零条当覆盖。记录器绑定完整计划行、来源运行、留存响应和追加式收据。后续异常审阅可撤销先前验收结论，旧记录仍保留。离线 Mock 只验证绑定和决策机制，实际字段效果与分页必须由具备授权的来源回执和审阅判断。

若被拒绝的发现源已有同一意图、父链哈希有效的下游 `browser_fallback`，且其真实回执已通过精确来源操作验收，工作投影会收起祖先重复的来源操作复审待办；历史拒绝仍保留，祖先不因此变为已验收，fallback 的候选分流、结果语义审阅和剩余范围仍需分别处理。

已确认范围变化使方向整体退出时，使用 `scope_cancellation.py --task-dir DIR --query-id ID --change-id CHG --reviewer NAME --reason TEXT` 追加取消。它要求当前范围版本、受影响方向及查询、已确认的商品变更记录相互匹配；不能仅因已有替代计划或希望提前收尾而取消。若一条查询仍服务其他有效方向，不得整体取消。历史查询、来源回执和计数保留。 精确例外仅限未提交的本地图形标识分类／视觉比对：旧行必须只由 `product.mark_inventory` 派生，当前已审库存为空且资产范围哈希确已变化，并绑定同一已确认变更、受影响查询及方向。该例外取消已不存在的旧本地目标；未来拟用品牌方向仍保留等待信息。官方检索、非空或未审库存、相同哈希及来源失败不适用。

选路按操作能力而非来源名：具备同等能力时先用适合的 API；API 缺分类、原文或动态状态而网页对应操作已验收时，可直接走网页，不制造 API 失败。来源只支持已知号时只用于号码核验。图片路线必须同时具备当前目标主图身份、来源操作能力、接收方及用途许可；不能换辅图或托管来绕过缺口。仍有未审结果或可执行必要动作时继续；用户信息／许可等待不靠时间流逝变成受限交付。

2.4 的美国专利／外观发现记录器另接受 `capture_transport=cua`：如实标注 `browser=codex_iab`（或实际桌面 Chrome）、`cua_browser_id` 与 `cua_tab_id`，不得冒充 CDP 会话。该入口仍须通过原计划绑定的 automatic 执行收据、实际提交、查询历史、结果集、截图和逐行页证校验；不接收人工业务操作证明，不自动验收字段／分页或授予来源能力。旧任务及其他记录器不开放此入口。

## CUA 的工作区、绑定与交接

CUA执行来源业务时仍使用原计划、原执行收据和正常来源限额；开发维护探针与商品任务分开记录，不改绑历史回执、不算商品召回。当前业务模式名basic_search是既有收据字段，不表示可把布尔表达式输入PPS Basic的Quick lookup。

1. 先核当前官方页面及同一浏览器的标签。基础页Quick lookup仅接受号码，Basic search按页面规则限定输入；复杂布尔、字段标签和统一计划表达使用官方高级工作区的Enter query text编辑器。首次采用页面中实际入口；入口点击没有打开工作区时，先核是否另开标签，再使用已有证据支持的官方高级工作区地址。不能对无变化的基础页连续点击Search或把未出现结果认成零条。
2. 高级工作区显示Console is already open时，只检查同一浏览器实际存在的官方工作区标签并复用。另开标签可能延迟出现；在原操作的有界等待窗口内刷新同一浏览器标签清单，不再次点击入口。窗口到达仍没有可核工作区时保留session_conflict接入依赖及恢复条件（能定位原控制台，或官方会话正常释放后出现可用编辑器），不循环创建标签、不清除凭据/会话来绕过，也不认来源无结果或全网无路由。导航超时不等于加载失败；读取实际页面确认，但不得借重导航重提交查询。
3. 提交任何查询前，在无已提交查询的工作区以Search History切换验证激活链。鼠标点击无效果时核对可见位置/遮挡及选中状态，可对该非提交控件使用正常键盘Enter；确认键盘激活有效后，该工作区使用键盘激活Clear、Search与历史面板。不得在查询已点击且提交状态未知时补按Enter，以免重提交。使用页面自己的Clear清空受控编辑器，读取确认空值，再以正常键盘输入完整编译表达；读取实际编辑器文本核对后仅提交一次。点击超时或返回不明，先查同一工作区结果与历史，不再次点击。基础页号码定位和高级布尔发现分别记录；号码定位不算盲测召回。
4. 留存提交前结果集编号和实际表达；提交后绑定当前结果集、Search History同编号行的查询和总数。历史行未出现时先查看当前可见历史表，再有界滚动至顶部/必要可见区，只读取已渲染行；结果出现不等于历史绑定完成。次数/时限到达保留未绑定材料，不能挑一行旧历史或手工填true。执行器与录入器只容忍英文大小写、引号外展示空格和括号空格；引号内空格、词语、字段、布尔操作符及分组不变。
5. 仍需核对历史、结果或后续页的Agent创建标签，在结束当前轮次前调用真实tab.markHandoff()并记录browser/tab/工作区身份；下轮继续需要再次标记。未标记标签可能在轮次结束自动清理。完整处理并留存后才关闭自己的标签；不关闭用户标签或其他任务的控制台。标记只保留工作区，不证明来源执行、身份绑定或能力验收。

### 已提交查询的瞬态历史读取故障

PPS 的旧工作区发生 GET queries／“Unable to get queries”错误时，保留原提交收据、结果集编号、已得行、截图与失败事实；结果已出现但历史未绑定时，不重提交、不认零条或成功召回。可在同一浏览器、同源官方工作区进行一次刷新，读取已存在的查询历史并恢复既有结果集绑定；刷新、版本变化或页面重新打开本身均不是证明。

只有实际当前证据同时确认原结果集编号、准确编译表达及一致总数，并保留同编号 Search History 行、结果页面及原执行收据关联，才按原录入／恢复入口追加确认。不得挑选其他历史查询、改写失败原 run／原行，或仅将 history_binding_verified 改成 true。一次刷新后仍空白、历史不可读或绑定不一致时，保留已得材料和绑定缺口，继续原有接入／恢复待办；独立读到的准确官方原件可走原线索入口，但不替代该查询的历史绑定。

只有真正取得并绑定的维护样本，才可按提供方/国家/权利/具体操作登记验收。页面可打开、离线匹配通过或接入指引已修订均不满足automatic验收。

范围取消记录另保留 objects/facts/directions 的完整 business_scope_sha256。仅在最近已确认变更版本及目标身份仍相同、该摘要不变时，candidate_links 等元数据更新可以保留取消效力；真实事实、对象、方向、目标或变更版本变化仍需重新审阅。历史无此证明的记录由正式记录器追加重新确认，不改写旧事件。

## API-first-v3 操作验收

新任务的第一次获准业务请求同时建立该操作的实际运行验收，记录接口响应、准确身份和地域检查结果。后续复用同凭据指纹、接口版本与权限的有效验收；真实异常或权限变化时重检。来源网站、后台授权、免费余额和隐私检查继续按现有合同独立执行。已有字段、同来源详情、其他 API、必要网页按顺序补缺，禁止只为再次确认而重复请求。

同一操作已经通过有效验收时，每个新回执仍校验自己的准确请求、身份、地域和响应契约，但不追加一份重复的操作验收。后来出现实际失败或响应验收异常时，旧验收不删除，仅停止复用；下一次成功业务响应可以建立新验收，不另发“验收探针”。

实际 2.4 API 调度器遇到确定性协议错误后，停止同一提供方、操作、查询编译版本及当前凭据／权限／适配器指纹的本批后续提交。OPS 的 `CLIENT.NotAcceptable` 从哈希核对过的原 XML 识别，HTTP 通用错误码不会使该故障漏掉。单案 `SERVER.EntityNotFound / No results found` 只限制该案，不停止其他对象。已发生的失败请求、原文和实际额度消耗保留；未提交项明确延期或阻断，不记成零结果，不新造一次网络失败。

维护审阅记录器另接受 `{"reviews":[REVIEW,...]}`：整批以同一任务／计划／证据快照验证，再追加原始收据、一次写入 task。完全相同的审阅内容和事实版本返回原收据；改动的判断保留新的追加记录。辅助计时写到 `runtime-timings.jsonl`，不进入事实或审阅摘要。
