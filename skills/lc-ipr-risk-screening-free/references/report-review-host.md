新任务还适用 [执行效率策略](execution-efficiency.md)：`adaptive-double-review-v2` 先测量完整材料，小包执行两个真实整合会话并记录 `integrated_execution`；大包继续下述模块协议。历史 `module-double-review-v1` 不迁移。两种执行方式的最终判断、逐单元双审和主审规则一致。

# 最终报告双审宿主入口

新任务使用 `final-double-review-v1`：可执行查询、已得材料、分流与比较完成后冻结共同输入，只进行一次最终独立双审。进度、日志、路径及不影响判断的计划元数据不触发重审；证据、产品或范围实质变化只重审受影响单元及总体影响。完整规则见[API 直接采信与一次最终双审](api-direct-final-review.md)。

## 大材料包及历史模块任务的并行执行

新任务默认 `final_review_execution_revision=adaptive-double-review-v2`，超出整合阈值时使用本节模块流程；已有 `module-double-review-v1` 任务继续本节协议。同一最终双审分为两条隔离链，每链包含技术（发明专利、实用新型）、外观（外观专利、未注册外观）和表达（文字／图形商标、版权、商业外观、维权信号）三个模块。六个原文审阅会话完成后，各链只汇总自己的三个结果一次；正常首轮共八个真实原生会话，默认最多四个同时运行。

```bash
python scripts/report_review_host.py --task-dir /absolute/task \
  --output-dir /absolute/new-module-review --max-parallel 6 --timeout 1800
```

`python` 是安装检查确认的解释器（macOS 通常为 `.venv/bin/python`，Windows 为 `.venv\Scripts\python.exe`）。宿主自己运行 readiness 与发布准备，**不必先单独运行 `review_readiness.py`**；准备未通过时它一次列出全部问题并拒绝冻结。审阅完成后先用 `prepare_adjudication.py` 生成主审骨架与冲突工作表，再写主审、发布，见 [workflow-efficiency.md](workflow-efficiency.md)。

模块按明确权利与依赖分包，共享产品事实、全部情景及具体限制保留。已注册公开原文读取实际文件并保留全文；实际图片复制到独立工作区，通过原生 `--image` 送入，包内逐张列真实来源及哈希。扫描 PDF 无文本时只记录真实提取限制，不能编造 OCR；有准确登记的页图才能实际阅读相应权利要求和图样。旧阶段审阅收据、进度文字与重复执行日志不作为本轮另一审阅者意见；API 原始字段中的历史、更新时间和原文保留。

宿主只准备一次 readiness 与发布准备问题集合，生成不可通过 JSON 伪造的 `PreparedReviewContext`。冻结及登记继续检查同一当前语义摘要、已引用原件哈希与冻结文件哈希，复用准备结果；不反复计算工作视图。搬迁清单中的可变任务台账不会被要求保持旧搬迁初值，实际引用的原件必须通过准确搬迁及原哈希校验。事实或原件变化时准备上下文拒绝继续使用。

每个模块必须覆盖自身全部国家／情景／权利的整体范围，制度免查须有实际规则引用（`best-estimate-risk-v1` 任务由冻结输入 `evidence.collections.institution_references` 的 `EV-INST-<国家>-<权利>` 条目满足，来自 `references/jurisdiction-rights.json`；提示词契约 `best_estimate_rules` 与其评级段落只在该标记下出现）；`best-estimate-risk-v2` 另加极高修订段：现行有效＋页面专利标注＋独立项要素对应即极高，权利人未具名只进假设；审阅文字直接展示给卖家，禁止字段名与规则术语；`material_observations` 只需 observation／limitations，来源引用由程序按 material_id 绑定）。v2 任务的模块包只完整保留入选、待补与未分流候选的材料，不入选候选的详情与原件替换为带分流理由的存根，任务管理日志不进包；校验仍用完整证据索引。模块输出被拒时写 `<输出目录>/rejections.jsonl`。具体候选未知原样保持 pending；`known-findings-risk-v1` 的运营评级另按已知适用具体风险汇总，未知只入进度和限制。每链汇总会话不重写模块行、信号或复用凭据，只形成当前总体、检索范围、限制与覆盖置信度。

整份与模块原文审阅使用同一状态合同：新输出逐行显式填写 `assessment_status: pending|assessed`，不能写 `completed` 或省略。`pending` 必须为 `risk:null` 并解释缺失事实；有依据的当前风险使用 `assessed` 和五级风险。已审信号及绑定任务的范围排除仅在各自既有条件满足时允许空风险，普通未知不能借此标为已审。`scope_applicability.status: applicable|not_applicable|unassessed` 属于制度适用性，不能代替审阅状态；制度不适用须实际证据，不自动变成低风险或任务排除。宿主保留原始输出并严格校验，不将非法状态改写为合法枚举；历史空值兼容规则不作迁移。

输出按 `1/technical`、`1/appearance`、`1/expression`、`1/summary` 及第二链对应目录保存原判断、真实原生日志、包、提示、图片和访问边界审计。最终文件为 `1/review.json`、`2/review.json`。`review_context.execution.module_execution` 保留各模块真实 session 及 summary session；单元原审来源取实际模块，不将 summary 的单一签名冒充全部模块作者。每个模型工作区都禁止读取全部其余工作区、任务目录和宿主输出，第二链不接收第一链当轮结论。

模块调用失败或判断无效时保存日志并报错，不自动重试、不改写等级。各审阅位的旧文件仍可通过原 `--previous-first-review`／`--previous-second-review` 传入；只引用本位未变单元，模块行及其原审来源保持原签名，变化单元和本链总体影响重新审阅。历史无模块标记任务继续以下原整份执行规则，不自动迁移。

任一会话失败、超时或宿主在后续校验处中断后，可先修复确定性的错误，再对**原输出目录**运行 `report_review_host.py --task-dir TASK --output-dir ORIGINAL_REVIEW_DIR --resume-existing`（隔离后端须与原运行相同）。宿主逐会话处理：原生事件日志包含完整、无工具调用的单次回合，且模块包和提示与重算结果逐字相同、原件观察合同有效、法律判断通过实际模块范围及字段校验、已留存判断及审计完整性匹配的会话直接复用，不重新调用；日志缺失、不完整或完整但原件观察缺失／错引用／空内容的会话，其目录改名保留为 `<模块>.attempt-N` 后以同一冻结输入、包和提示开启全新会话（全部改名记录写入 `freeze-receipt.json` 的 `resume_attempts`）；已存在的模块包或提示与重算结果不同则立即拒绝。成功模块保留原执行身份，汇总包中的模块摘要也保持原值；只有失败位置或实际输入改变的位置才需新会话。两个最终审阅均成功且当前输入、原件、审计、执行链和双审关系复核通过时，直接返回原路径，不重写成功审阅、原生日志、审计、汇总输入或成功冻结回执。部分失败先只读核验所有位置，再安排失败位置，不先改动前面的成功位置。完整但原件观察不合格或本轮法律输出合同不合格，只在显式恢复时归档并重跑该模块，不自动重试；已注册来源先完成完整性校验，旧收据或未知校验故障保持硬阻断；文件、图片、原判断或已有审计被改动则拒绝，不能归档后掩盖篡改。显式恢复仍受同一累计预算约束，预算耗尽保留原结果和失败日志，不形成成功收据。旧审计有进程号则保留；中断前未落审计的模块明确标注进程号和退出码未留存，以原日志中的完整回合证明模型输出，不编造原生进程信息。任务图片编号只有登记路径、字节数及哈希全部匹配才可作为**商品侧**比较引用，不能充当第三方权利或状态的证明。

新生成的模块审计以 `execution_identity_revision=stable-native-run-id-v1` 和 `run_id` 成对保存真实执行身份；验证材料、日志和输出后先原子保存，再供汇总与最终登记使用。已有审计不补字段、不重签。旧身份从本链原最终审阅和当前／归档汇总中恢复，所有可核验依据须一致；无汇总审计时必须有完整无工具原生日志及逐项匹配的模块摘要，只有输入包不足以证明原身份。旧审计无身份、无可恢复原记录时，仅在原输出树无下游汇总、归档、最终审阅或成功声明的情况下保留确定性恢复规则；有下游迹象但缺件、损坏或冲突则拒绝恢复。

初次执行仍按原槽位顺序分配临时工作区；续跑先验保留位置，第一次需要新进程时才创建完整槽位与隔离探针。全成功续跑不创建临时目录、不探测登录或运行新模型，原 CLI 删除不阻止纯验证；失败位置仍须满足原程序绑定和隔离规则。模块与视觉宿主在执行线程、子进程和日志句柄结束后清理本次持有的临时目录，正式材料与历史尝试完整保留。清理失败输出路径和原因，不覆盖原错误、不重跑模型。任务累计预算与性能观测仍按原合同执行。

整合与汇总位置在首次执行和续跑时共用最终声明、置信度及依据的原接受规则；专业模块保留各自合同，不要求汇总专属字段。原件观察及未传送原件限制也参与同一分流。只有明确的模型内容异常可在显式续跑时归档重做，完整但无效的输出及已有审计保持原字节；工具调用、输入/原件/审计损坏、身份或隔离冲突仍直接拒绝。不得补默认值、强制转换或代填模型结论。唯一的确定性例外是行级证据引用并集（`row-evidence-ref-rollup-v1`，见下一节）：它只把同一行嵌套字段里已经出现、且在登记库中真实存在的证据 ID 并入该行自身的 `evidence_refs`，不产生任何新的引用、结论或等级。

### 行级证据引用并集、归档尝试提升与重试上限

- **行级证据引用并集**：`_validate_row` 要求每行的 `evidence_refs` 包含该行全部嵌套 `*evidence_refs`。模型常在嵌套字段里引用了一条已登记证据却漏列于行级列表；此时宿主按纯函数补全该行的 `evidence_refs`（只并入同一行已出现的字符串 ID，保持原序后追加，幂等），其余全部规则一字不变地继续校验。模型的原始输出（`agent-judgment.json`）、事件日志、审计及其哈希保持原字节；被补全的行与 ID 记录在 `module_execution.row_derivation`（只在确有补全时出现），`validate_execution` 复算比对，无标记走原路径。引用了不存在的 ID、非字符串或缺少其他必填内容仍按内容不合格处理。
- **逐位置捕获**：六个模块会话结束后全部先落账与校验，再报告第一个失败；一个模块的内容问题不再使同批其余模块的真实审计退化为“由留存日志恢复”。
- **归档尝试提升**：`--resume-existing` 时，若某槽位已不可复用，宿主先查其 `<模块>.attempt-N`：包与提示逐字相同、事件日志完整、审计与冻结输入匹配，且（按当前规则含并集派生）已通过校验的尝试，会被提升回当前位置（原槽位改名为新的 attempt-N，记录于 `resume_attempts` 的 `promoted_from`），不再重复付费。
- **重试上限**：v2 预算任务每槽对“已完成但被校验拒绝”的回合最多重试 1 次；中断、超时或失败的回合不计为内容失败。超过时在归档和计费前报 `FINAL_REVIEW_SLOT_RETRY_LIMIT_REACHED`。
- **启动前干跑**：`--preflight` 只读不写，列出运行时钉住（`native-runtime.json` 的 CLI 路径与哈希）、就绪问题、三个模块×两链的提示字符数及 1,048,576 上限、留存槽位状态、估计所需时长与剩余终审额度；有任一阻断退出码为 1。未启动任何会话的输出目录（只含宿主自己写的冻结输入、包、提示和图片副本）可直接重用，宿主自动清理后重新开始。
- **网络中断重跑（r5d10）**：带 `pipeline_robust_revision` 的任务，本次新跑的模块或汇总会话若因网络中断失败（事件流里 `error`/`turn.failed` 的消息含 stream disconnected、transport error、network error、error decoding response body、error sending request 或 connection reset/closed/aborted），与"内容被拒"的会话一起在同一次终审内重跑一次。时间判断沿用 `in_run_retry_allowed`，以该槽位实测秒数加汇总预留为准；超时和其他执行失败不重跑。这类网络失败不计入 `failed_complete_turns`。新任务的终审额度改为 1800 秒，每多一个国家加 600 秒，上限 3600 秒；取数额度仍为 1200 秒。
- **未完成会话计入估时（r5d11）**：预检估算某槽位耗时时，同一提示词的已完成会话取实测秒数；被网络切断或超时的会话取其已运行秒数加 120 秒。因此额度已证明不够时，预检会以 `EXECUTION_REVIEW_BUDGET_INSUFFICIENT` 拒绝开跑，不会再白跑一轮。`run_pipeline.py` 把所有者追加命令完整写进输出的 `owner_action`：追加秒数为 2×预计−剩余，上限 1800 秒，以留出一次网络重跑。
- **模块材料范围（r5d12，`review_packet_scope_revision`）**：每个模块只收自己权利类型的专项事件，其他模块的事件改为存根（含哈希）。同一候选、同一申请只发一份全文：已留存授权文本时，授权前公开文本改为存根；同一公开号同时有 Google Patents 页面和 PDF 文本时，PDF 改为存根。存根注明全文由哪条证据发送。冻结输入、摘要和校验登记都不变，所有证据编号仍可引用。B0GLNPC6K8 的实测：技术模块提示从 911,582 字符降到 440,054 字符，同时终审前筛查排除了 3 件失效专利。
- **原件读取与清单同一规则（r5d14）**：`attach_originals` 认定公开原件的规则，与材料清单（`review_material_policy.file_inventory`）一致：有 `source_url`，或者是 API 记录自带、带 `source_field` 的媒体行。外观专利超过核心登记的 10 幅附图时，其余附图只以 SerpApi 媒体行存在，以前清单列了却不读，导致 `ADAPTIVE_ORIGINAL_MANIFEST_INCOMPLETE`；现在全部视图都读。
- **所有者追加额度**：终审额度用尽且确有价值时，只能由任务所有者在终端运行 `scripts/extend_review_budget.py` 追加（≤1800 秒、≤3 条记录、需键入确认；任何计数和策略哈希不被清零或改写，追加记录含原因和既有计数）。

完整事件日志中的模型正文 JSON 无法解析、权利类型/状态填写错误类型、误选当前材料已变化的历史单元，均按内容不合格处理。外层事件日志损坏仍拒绝；正文错误也须先核验留存宿主文件、隔离与图片。复用资格由宿主对已核验旧收据和当前冻结材料计算，不采信模型自行声明；只重做失败位置和确有必要的本链汇总。

## 报告必出的终审（r6 起的新任务）

- 只跑六个模块会话（两链×技术、外观、表达），链汇总由程序按各模块总结写成（`program-chain-summary-v1`），不再有汇总会话。
- 每个模块回答经 `module_review.settle_module` 结算：程序补齐字段、去掉不属于本模块或未入选候选的评级行、补齐漏写单元；冻结登记中不存在的证据编号删去，仍不合规的行转为待定（记录在 `module_execution.module_repairs`，发布时由 `module_repair.derive` 重算核对）。
- 回答无法解析或缺 assessments 时，重试一次并在提示词末尾写明原因（槽位身份按不含反馈的基础提示词计）；网络中断立即重跑一次；仍失败、时间或额度用尽、重试上限已到的模块记为 `fallback`（`<链>/<模块>.fallback/fallback.json`），这一链该模块全部待定。
- 截止时间：`--stage-deadline-seconds`（流水线按全程 2400 秒减去已用时间给出，至少一个会话的时间），每个会话最长 600 秒；额度不足只记警告，不再要求用户追加额度。
- 预检与正式运行使用同一模块校验（`judge_module`），重试上限已到的槽位预检显示为 `fallback`。

## 运行环境、隔离后端与选项

整份与模块提示共用 `required_product_scopes`，每位独立审阅者须覆盖每个适用情景／国家／权利的无候选 `product` 整体范围。候选、`own_brand`、未来或信号行不能替代；证据不足仍以整体 `pending/null` 行解释，不填低风险。登记、聚合及裁决准备拒绝漏项，模块仅检查本模块权利；裁决不能代填一位审阅者缺少的整体范围。原始输出与账务保留，不自动重跑。无情景定义的旧任务不被静默扩展为新情景，完整登记边界始终要求范围完整；已有原生/模块收据在聚合中同样严格。进度视图保留合法已有行并列出原生收据漏项，历史手工阶段审阅保持原有证据限制及部分交付规则，不将阶段交付标为完整双审。

- `--isolation auto|macos-sandbox|tool-free-process`：macOS 上 `auto` 即 `macos-sandbox`（`sandbox-exec` 内核读边界，永不自动降级）；Windows 与其他系统上 `auto` 即 `tool-free-process`：同一条禁用全部工具／插件／MCP 的 `codex exec` 命令、每会话独立临时工作区、直接以 `codex login status` 检查登录，并由宿主逐条校验事件轨迹只允许 agent_message／reasoning／error。它**没有内核级读边界**：每份审计写明 `isolation_method=tool_free_process`、`kernel_read_boundary=false`，并在 `isolation-policy.json` 记录 codex 二进制哈希与版本、禁用特性、工作区文件清单，且拒绝工作区上级目录存在 `AGENTS.md`。校验器（`validate_execution`）按方法分别核对，恢复不得跨后端。整份历史两审路径仍仅限 macOS。
- Codex 二进制：`--codex-binary`，否则 `LC_IPR_CODEX_BINARY`，否则按既有应用目录与 PATH 顺序逐个检查原生文件和必要能力，跳过不兼容候选；显式参数或环境路径失败不静默回退；`.cmd`／`.bat`／`.ps1` 包装脚本一律拒绝。
- 模型与上下文参数读自 `references/review-host.json`（默认 `gpt-6-astra`、上下文 872000、压缩阈值 800000、推理强度 medium；`tool_free_codex_sandbox` 默认 `read-only`，仅当 Windows 真机冒烟显示该 Codex 版本启动即拒绝 `--sandbox read-only` 时才改为 `danger-full-access`——所有工具仍被禁用，轨迹校验照常生效，且写入策略文件）。
- `--timeout` 为每会话总时限 30..3600 秒（默认 1800）；`--max-parallel` 1..6（默认 6：三个模块 × 两条链的六个会话同时开始，实测一次通过由输出速度决定，并行 4 的模块阶段 509 秒、并行 6 约 375 秒）。提示词、事件日志一律按 UTF-8 读写，与系统区域设置无关。
- 单个会话的提示超过 1,048,576 字符时在模型调用前明确拒绝，不截断材料；该任务须缩小范围后重新冻结，不能手工录入替代。
- 模块宿主每次运行只检查一次 ChatGPT 登录；历史整份路线保留逐工作区登录检查。

## 注册原件与执行观测

两条路线的公开原件均复用同一个注册原件读取器：仅解析冻结材料中有 HTTP(S) 来源、实际路径与匹配 SHA-256 的原件；不扫描未注册目录、不额外联网。读取器对实际读到的同一份字节再验登记哈希／字节数；正文、PDF、图片及 XLSX 解析均使用这份已验缓冲区，XLSX 不重新打开路径。原件登记扫描与提示使用同一材料投影，先排除 result_task 旧快照及嵌入二进制字段，避免旧快照附件回流。JSON 原件为实际解码字符串或完整 JSON 文本，不以文件名/摘要替代正文；损坏 JSON 或字节不匹配拒绝送审。HTML 提取正文、PDF 提取文本的限制保留，未提供的视图不算已读。图片按 `attachment` 绑定实际字节，两位分别获得相同原件副本。

两条路线在发送前将包、提示、隔离文件、挂载视图及图片副本与内存合同绑定；发送前与原生结束后复核同一字节哈希。观察按已绑定字节解析的包校验，不能用运行后可变包降为 v1；审计引用发送前哈希。发现变化保留原生输出并拒绝收据。该机制不宣称防御同宿主恶意进程在检查间瞬时改写再还原附件。

历史 `public-originals-v2` 及新任务的 `public-originals-v3` 公开材料要求原生输出 `material_observations`：每个 `material_id` 恰有一个对象，包含原样 `source_refs`、具体可见内容 `observation` 和明确读取限制 `limitations`。漏件、错引用、空观察或缺限制均拒绝登记；宿主不代写观察。该结构检查只证明绑定完整，不自动证明观察正确、法律复核充分或供应商授权。历史 v1 已签收据仍按原合同校验；旧模块输出包/提示与新包不同则不能静默恢复，须保留旧结果、评估原件读取缺口后另开运行，并沿用累计预算。

新任务 v3 材料包另分类正式记录器回执和未传本地原件，详见[执行效率策略](execution-efficiency.md)。内部回执内联内容须经过原件和合同核验；未传本地原件正文不进入提示或附件，审阅必须保留未读限制，不得用上游事实冒充已读原件。

新 v2 效率任务在首次原生执行前保存 `native-runtime.json`（程序路径、当时哈希及隔离后端）。续跑先读取原运行绑定，成功位置不重写审计或日志；需要新进程时程序字节或后端变化则拒绝。旧记录不补造程序哈希；能从原审计可靠确定程序时沿用，记录矛盾或无法确认且仍需进程时明确诊断。安装新 CLI 不改变既有运行绑定；全部成功位置的验收无需重新选程序或探测模型能力。

每次原生调用实时保留事件及 stderr，并写 `events.execution.json`：实际进程号、提示哈希/字节数、首事件、turn 开始、首 reasoning/agent_message、turn 完成、最后事件、退出原因及可获得的真实 usage。没有实际事件或 usage 就是 null，reasoning 输出是输出用量的子项。时间是宿主以 100ms 间隔看到 CLI 事件的时间，不是网络 TTFT；5 秒日志刷新不算业务进展。

观测中的 `process_exited` 只表示进程正常退出，`review_validation=not_performed` 始终保留其观测层含义。必须继续通过完整回合、原件观察、评级字段、证据引用、实时摘要及两审独立性门槛，才有 `pair_validated` 收据。失败和超时仍保存已取得的原件包、提示、图片和部分事件；不补造风险结论、不自动重试。`--timeout` 仍被已有累计预算裁短，恢复或换输出目录不能重买时间。

## 历史整份执行规则

无模块标记的历史任务继续使用整份两审执行，规则见 [legacy/report-review-host-whole-input.md](legacy/report-review-host-whole-input.md)；新任务不读。该路径仅 macOS。

完整范围识别以输入摘要已绑定的任务合同为依据：当前连续整份/最终路线及模块要求产品整体范围，不能因收据缺少host_audit/module_execution降为阶段审阅；存在但不是对象的审计字段拒绝。necessary-work-v1/v2历史源范围阶段合同保留旧部分交付，不升级为当前完整双审；修改任务合同版本会改变审阅输入摘要。完整登记仍要求整体范围，进度保留逐行合法的部分工作并持续列漏项，主审不能绕过完整范围门槛。

聚合结果的review.scope_contract区分whole_product与legacy_stage_scopes，并保留两位product_scope_gaps；历史阶段范围不能据此声称当前完整产品清查。此字段是计算结果披露，不是审阅者可提供的降级授权。
