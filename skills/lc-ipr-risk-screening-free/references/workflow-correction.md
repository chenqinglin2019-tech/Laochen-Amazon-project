# 流程纠错与必要工作契约

适用于显式 `workflow_correction_revision=workflow-correction-v1` 的新任务。沿用现有情景、分流、来源及双审流程；旧任务不原地补字段或重算旧摘要。新目录可以复用合格原件，但原时间、来源、字节和旧回执保持不变。本文为本次细则的唯一维护入口。

## 输入与更新范围

- 显式补充清单优先，否则读取任务内 `supplemental-evidence.json`；不存在才视为无补充，存在但无效（包括空对象、断链符号链接）必须报错。规划、分流、批次执行、最终评估和报告使用同一解析与校验规则；单次未变化快照可复用校验，源文件变化仍须重验。
- 本任务原始证据、候选线索及其清单/文档、原始回执和产品图中的相对文件路径按输入 `task_dir` 解析；补充清单沿用显式 `evidence_root` 的相对路径语义及允许边界，历史绝对路径仍须在该边界内。发布、独立构建与校验传递同一源目录上下文，不向冻结任务补字段、不搜索同名文件、不扩大根边界；未带纠错修订或未传目录的独立内存调用保持原行为。
- 产品结构、拟用标识、素材用途分别绑定判断。新增或替换自有品牌、Logo、用途归属重开相应商标判断，不改变未变化的专利结构事实；结构或材料变化重开受影响结构权利。
- 图片/原文内容改变是事实变化；路径、重复取证时间及说明措辞不是。商品规格仅剔除明确的零售统计字段，不用包含 `rating/rank` 等词的宽泛匹配过滤物理规格。
- 补充原文通过完整公开号、国家、权利类型及文件身份关联候选；分流、评级、选图共用关联入口。新保护文本、首次取得且以前未审的相关页图或身份纠正只重开对应候选。重复同一原文、同页重渲染不触发全量重审；同族另一公开号不继承决定。
- 分流冻结/导入必须使用同一证据快照派生的候选视图。新分支在既有导入锁内复用 merge 的核验/商品服务映射作纯内存校验；新证据已入库但候选仍为旧 `not_checked` 等状态时，以 `TRIAGE_CANDIDATE_VIEW_STALE` 拒绝整批写入，先完成候选合并并确认实际已读依据再追加决定。不逐源重跑 merge、不修改旧决定哈希、不因引用是派生字段而忽略真正新增保护文本或状态。

## 必要审阅

候选书目记录的结果行序号和整页结果截图路径/哈希/字节数属于操作留痕，不参与新版分流事实摘要；原回执及文件仍完整校验。标题、保护文本、状态、候选附图/标样和未知扩展字段仍保留，不能通过忽略截图元数据隐藏实质更新。

- 从情景、国家和必要权利范围生成范围审阅义务，独立检查范围结论、有效不适用判断和入选候选比较。删除一整个范围行会产生漏审，不能以空列表提高完成度；未入选候选仍无需逐件五级评级。
- 当前有效权利不能移入未来申请而免除当前审阅。未来信号必须精确关联候选、国家、权利、情景和状态依据；实际未授权申请可完成相应未来审阅，未知或冲突状态保持待核实。
- `future_signal_basis` 记录申请身份、未授权/待审状态的实际依据、引用及理由。未来事件可以与当前权利并列，但不得冲销当前风险；一个审阅者标为未来不等于双方完成必要审阅。
- 两轮及主审绑定同一冻结输入。现有中高风险、置信度和工作完成度仍分开；不补默认等级，不以局部排除推导全面低风险。

## 执行与恢复

- 已确认的 USPC D 开头外观分类仅生成外观召回，不为实用专利/实用新型生成同类空转动作；普通 USPC/CPC 维持原适用范围。历史已生成行保留，误配动作追加有依据的撤销，不记零结果或覆盖完成。
- 回执保存真实提交事实：已提交、未提交、未知。提交前适配/登录失败不消耗来源尝试；真实提交失败计入；未知先核对原回执，不能自动重试，也不能默认认定已经提交。
- 浏览器对 Python 授权器的回调使用调度器当前解释器，避免系统 Python 缺依赖造成双端判断不一致。已知授权器失败发生在出网前，明确记录未提交；历史误记为未知的精确 guard 失败须经 `review_pre_source_guard_failure` 追加原记录哈希绑定的审计后恢复。该入口不接受普通超时或真实提交，入选核验与待补充均不能绕过未知提交检查。
- 临时等待、尝试耗尽和永久撤销不同。旧缺失字段不一律改成未提交；恢复以追加、绑定原动作和原记录的事实处理。失效分流或明确撤销仍不执行。
- 待补充先检查已留存合格内容；可由 Agent 直接阅读的，不重新出网。必要出网时声明所需事实与读取范围，分别取摘要、代表图、保护内容和当前状态。资料满足后返回分流，不把摘要成功当成完整核验或当前有效证明。
- 摘要按原文实际章节边界读取，PPS 的 `Background/Summary` 等后续标题不属于摘要；保留完整原始文本，不能为了纠正摘录而改写历史回执。已留存的必要保护文本可以直接阅读，不因缺少独立 PDF 再次出网。
- 新建 PPS 号码读取动作绑定 `query_compiler_revision=ppubs-quoted-record-v1`，将原子号码编译为带引号的 PN 字面量，匹配实际页面回写。历史无标记者保持原编译；不放宽查询历史、结果集合和编辑器三方一致校验。
- 统一下一步工作视图由既有台账、计划和执行证据派生，不维护第二份人工队列。本批次结果与全任务剩余必要工作分开；过期、撤销或已替代的旧登录挑战不要求本轮用户处理。
- 独立待办命令与执行器使用相同的来源可用性规则。浏览器路线尚未实测不自动等于等待用户；有适配器时由 Agent 验收，无适配器或禁止路线明确报内部/策略限制。待补充动作尚未写入计划时，保留动作身份、所需事实和待规划原因，不能标成已取证待审。
- 发布前记录仍可执行、已取证待审、待访问、待用户独有资料和真实受限工作及停止原因。阶段性报告可以保留，但不能将尚未执行写成网站受限或全部完成。

### 定向读取与下一步入口

`needs_info.next_actions` 的 `source_lookup` 保留 `provider/operation/params/action_id/purpose/max_attempts=1`，另须填写 `required_facts` 非空去重数组和 `reading_scope` 对象。事实枚举为 `abstract`、`representative_figures`、`protection_content`、`current_status`、`goods_services`；`reading_scope.level` 使用同一枚举。代表图必须指定已确认的 `reading_scope.page_numbers`（1-based 正整数去重数组）；页码未知时先取摘要或文献目录，不猜页码。PPS 公布原文路线不能满足 `current_status`；完整保护内容达到原有页数/时限边界时仍保留截断。

已有准确原件时可使用 `kind=agent_read`，填写 `evidence_refs/action_id/purpose/required_facts/reading_scope/max_attempts=1`，不填写 `provider/operation/params`。调度器发现已登记、完整案号及哈希匹配的原 PDF，也会派生 `agent_read_required`；这只表示原件可读，`complete=false`、`satisfied_facts=[]`，不生成来源回执。读后追加新分流决定；合格 TSDR 既有完整商品服务/状态可按实际事实复用，但不替代新情景判断。

只读运行 `python scripts/next_work.py --task-dir /absolute/run` 获取当前 `entries/counts/unresolved_scopes`，工作按 `scenario_id/jurisdiction/right_type` 定位。状态为 `ready/awaiting_review/awaiting_access/awaiting_user/submission_unknown/blocked`；其 `status` 仅表示必要调查与分流，不替代独立审阅完成度。浏览器用 `run_browser_plan.py --query-ids Q1 Q2`、API 用 `run_api_plan.py --query-ids Q1 Q2` 批量执行准确 ID；禁用路线不因指定 ID 而启用，API 可选动作仍须显式 `--include-optional`。输出 `batch_status` 是本批次状态，`work_status` 保留全局必要缺口；逐条源回执独立保存。确认未提交后的恢复说明追加到 `action-recoveries.json`，绑定原 run ID/哈希和原计划行哈希，既不重写旧记录，也不证明本次请求已经成功提交。

## 必要工作发布门禁（necessary-work-v1）

以下为 `completion_policy_revision=necessary-work-v1` 的冻结语义。当前新任务使用下节 v2；两个修订均纳入审阅摘要。不能补标记或改写旧查询以迁移已经执行的任务。

- 唯一执行闭环为：读取 `next_work` → 补计划、检索、阅读或专项调查 → 登记证据 → 合并与分流 → 重算待办 → 冻结输入 → 独立双审 → 发布检查。API 或浏览器批次结束不代表 Agent 工作结束。
- 先完成素材用途和标识盘点审阅，再分别执行图形商标、版权、商业外观调查。确实不适用也须有实际图像、标识及理由支持。术语修正、计划补充、可读原件与比较保持可执行；缺账号、禁止路线、无合格适配器及限流等待保留具体阻碍，有已授权替代时先完成替代判断。
- 已完成公开调查、但仍需用户自身供应链持有的资料时，复用该调查的 `outstanding_actions` 追加 `kind=user_information`；保留原调查记录，不造候选或第二份阻碍台账。动作须有 `action_id/purpose/question/reasoning`，`owner=user|supplier`，以及绑定本步骤已登记原文和实际图像的 `evidence_refs`。`evidence_needed` 仅接受 `supply_chain_authorization`、`independent_creation_records`、`private_sales_and_marketing_records`、`product_manufacturing_records`。资产范围、盘点及公开步骤均合格后，`next_work` 才派生 `awaiting_user`；未做公开工作、混入 Agent 动作、无原文图证、泛泛 `unresolved` 或陈旧范围仍不能形成外部阻碍。新追加调查优先于同查询的旧完成记录，收到资料后需重新审阅并追加记录。
- `next_work.py` 可选 `--first-review`、`--second-review`，派生 `review_work` 列出各轮缺少的必要范围审阅，不改变原调查 `status`，不维护第二份持久化台账。未入选候选无需逐件评级，但必要“情景 × 国家 × 权利类型”不可整块漏审。
- 两轮阅读同一冻结输入，第二轮不接触第一轮结论；保存真实会话标识及输入摘要。程序校验绑定，Agent 执行流程负责实际独立性。空 `assessments` 表示尚未审阅；有依据的 `pending` 范围行表示已经审阅但暂不能定级，两者不可互换。
- `publish_report.py --mode final` 为新策略默认：必要调查、分流、核验和范围双审完成，现有业务完成度校验通过。`--mode stage --stop-reason` 要求仍可执行的 Agent 工作已处理、两轮逐范围已审、剩余工作有明确阻碍及证据。笼统“数据不足”或停止说明不能覆盖待办状态。
- 发布前基于同一输入重算待办，在写报告文件前执行门禁。`publication` 保存发布模式、停止原因、输入摘要、待办摘要及脱敏来源能力快照；独立构建与验收共用规则，离线验证历史产物不读取本机当前凭据。输入变化使既有发布绑定失效。
- 通过文件校验不等于排查完整；“0 个入选候选”不代表全面核验。缺口不自动升降风险，局部排除不外推整体低风险；原因写入既有说明栏目，保持报告布局、CSS 和格式锁不变。

## 有界取证交付（necessary-work-v2）

本节为 v2 调度、停止和发布的唯一规则入口，优先于各参考文档中的旧 v1 完成限制。原鉴权、来源消费授权、费用上限、证据真实性、风险依据和独立双审不变。

- CLI、执行器和发布/独立验收由同一冻结输入派生完整待办，包含 API 发现、合并、轻审、原文阅读及专项调查。稳定 ID 绑定具体范围与动作，不维护第二份人工队列。
- 同一查询历次取得的真实材料都须校验、合并和审阅；最新失败、零结果、未知提交或取消不能隐藏旧阳性材料。API 提交仍检查实时凭据，输出待办与 CLI/发布共用任务能力快照；刷新能力必须显式执行原预检，不静默替换快照。
- 初始查询按适用国家与权利轮转，随后补充各维度和同义词。首轮审阅后，预留规划名额优先用于未首查范围和有依据补搜。预算预留不是额度耗尽；取消且明确未提交只释放规划名额，不退款已提交/未知消费。
- 来源能力按国家、权利、操作及编译版本解析，保留真实回执支持的准确操作验收，不升级整站。没有可用 API 时，可基于绑定任务/范围/能力快照的判断启动允许的有限浏览器路线，无需制造失败 API 请求。
- 保留现有同意图两轮细化、每查询八页、每必要范围两条有限浏览器查询及每条五十个候选的上限。换名字或来源不重置同一调查目的。真实图形不适用审阅应关闭对应发现意图，不反复要求不存在的 Logo 词。
- 两条浏览器查询只有真实提交、取得合格回执且全部材料已审，才能支持该范围其余检索维度的有界限制；两条计划预留不算调查完成。语言绑定具体文本/描述查询，已有合格目标语言计划不派出孤立翻译待办；真正缺词或编译时明确列原术语、目标语言及修正动作。
- 普通已提交失败须先完成原允许的一次恢复，当前阻碍审阅和所有计数回执完整后，才可作为范围受限依据。原回执审阅后仍未知的提交另标“未知提交保留名额，无法继续本轮查询”，不称检索完成或实际消费耗尽，不释放名额、不重复请求；未审未知仍阻断发布。
- 有界调查完成须已取得候选全量分流、可读必要材料已读、必要比较和范围双审已完成。有效的有限发现停止仅记录本轮边界，不填补官方 coverage。可释放的预留额度、未修正语法、未读或未审材料仍是 Agent 工作；已取得的可读材料必须审阅，双审始终基于同一冻结输入且第二轮不得读取第一轮结论。
- 缺少合格路线、访问受限、真实额度耗尽或达到既有尝试边界，可保留未经官方核验的证据。停止判断绑定原查询/回执或具体能力依据，不能仅填写泛泛停止原因。
- 没有合格路线时，允许由准确调查意图、术语、现有来源授权、范围规则及实际能力快照证明编译后的路线集合为空；独立发布重新计算该证明。缺失能力检查不等于无路线，也不能虚构失败请求来填证明。
- `--mode auto` 默认选严格完整的 final，否则仅在有界门禁通过时选 evidence；不持久化 auto，不自动退成 stage。stage 保留显式临时交付。evidence 保留 assessment 的 incomplete、coverage 缺口和 unknown；真实受阻时可交付不完整证据报告，但未执行不得冒充受阻；文件独立验收通过后才标交付完成。
- `partial-evidence-v1` 仅在报告交付层增加内部技术失败例外：必须有绑定当前来源、查询及计划行摘要的真实失败记录，不能用测试/模拟标记记录、未提交的计划或笼统停止说明代替。仅有浏览器状态快照时还须验证任务内已留存的失败采集文件及哈希；失败回执含可读候选/材料时不得借此例外跳过审阅。例外不改原待办、执行条件或恢复规则，也不新增修复/重试；未执行、内部错误、访问限制分别披露。
- 定稿生成的 `assessment.publication.delivery_status=ready` 仅表示可发布，不能冒充文件交付；报告统一模型在临时目录生成 completed 视图，五产物及原文件独立验收通过后才复制到交付目录。公开 build 与 publish 共用此边界；stage 仍为 partial，验收失败不交付新报告。
- 报告逐项区分官方已核实、来源观察、推断、未知及冲突；列来源链接、原取证日期、支持事实、未核验事项和影响，并单列已查、命中、无命中、失败、未执行、截断、提交未知。公开原文不证明当前效力，来源标注 Active 不等于官方确认。
- 只有失败记录或摘要且不足以评级时，相关范围保留待评和缺口；失败不是证据支持的低风险依据。`partial-evidence-v1` 的不完整报告可在不改原始 pending/null 的前提下使用低/`policy_fallback`，所有派生置信度为低且显示未排除侵权风险；有依据的中高极高风险继续显示，不以局部低风险覆盖整体未知。鉴权失败、身份/引用/文件损坏、范围漏审在所有模式都阻断。
- 相同冻结输入重算保持相同待办；产品、证据、来源能力或已授权额度实际变化才重开受影响工作。历史材料仅在新目录按原身份、哈希和时间复用，重新分流和双审，不改旧回执。

## 核心图证与报告

新生成报告使用 `visual_policy_revision=core-risk-evidence-v2`；历史 v1/无标记产物仍按原规则只读验证。中/高/极高筛选、情景隔离、必要产品对照和关键反证保持不变。

核心媒体索引只读取正式 evidence collections 和补充清单的直接登记项；嵌套阅读回执里的同名 EV 只是引用，不能覆盖原文或产品图片登记，嵌套未登记媒体也不能升格为证据。正式登记的冲突 ID 拒绝发布，旧视觉修订保持原索引语义。

页图除了原有 `source_document_sha256/page_number/visual_role`，增加 `page_verification`：

- 公共字段：`schema=IPR-PDF-PAGE/1.0`、`source_document_sha256`、真实 `page_count`、1-based `page_number`、`image_sha256`。
- 受控生成使用 `method=controlled_pdf_render`、`renderer=pdftoppm`、`render_parameters={dpi,format:png}`；`pdf_page_evidence.render_page` 只生成指定真实页面，不覆盖现存图片。
- 旧图片实际核对后可使用 `method=agent_page_verification`、`reviewer/reviewed_at/reasoning`。这些是已完成的人工智能阅读记录，不能靠文件名或旧页码自动填充；取证日期仍保留原日期。
- 发布检查真实 PDF 页数、页码范围、子父案号/国家/类型及文件哈希。源 PDF 不可读、来源链缺失或冲突时保留图证缺口和风险；不猜页码、不重绘原文、不在每次发布重渲染全册。

新修订报告模型 `compact-evidence-v1` 将完整分流记录放在 `report-data.json.decision_records`，队列用稳定 `decision_ref` 引用；各情景数量和全部待办不变。HTML/Markdown显示具体缺口及离线完整索引，manifest绑定数据文件和记录摘要，不重复嵌入完整台账。

`publish_report.py` 只接受新输出目录：完整评估一次→同进程可信、一次性上下文构建→独立重算验收。v2 先在临时目录预验收报告，再复制已验收字节、最后交付 HTML；单独 build/validate 使用相同校验，不存在通用跳过验证开关。附件读取/复制按精确文件身份去重，不减少来源真实性核验。

## 性能与验收

在现有不可变快照内建立精确候选、证据、分流、计划及撤销索引；输入变化后重建，不能用时间戳或跨运行缓存替代真实性。批次复用不提高同源并发，逐动作仍检查有效性；双审保持独立。

针对性回归必须覆盖：有效权利误归未来、整块漏审、作用域更新、重复取证、提交前失败恢复、未知提交、按需原文成功、历史批次污染、错页/错父文件/冲突案号、图证复用、单条与批次等价及篡改拒绝。先窄测试，再 fast/release/格式与离线布局；真实来源执行和召回验收另列。相同冻结样本各测三次中位数，不把本地速度外推网站等待或整轮耗时。
