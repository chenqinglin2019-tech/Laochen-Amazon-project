# 产品驱动召回验收

新 `workflow-correction-v1` 必须额外通过[纠错反例与性能验收](workflow-correction.md#性能与验收)，包括已授权权利误归未来、范围漏审、提交恢复、轻量补充和 core-risk-evidence-v2 页图定位；这些测试不替代下文真实召回。

召回修复必须分别报告：离线回归、真实执行、产品盲测、覆盖完整度。`verify_skill.py` 不访问数据源，只验离线逻辑与报告布局；不得据其全绿宣称能找到产品专利。

## 正例与真值

由独立验收方核对产品与专利原始文献/必要附图的对应关系，保存真值文件。只有相同标题、品牌宣传或用户一句“有专利”不足以确定具体号码及权利类型。实用专利不能替代外观正例。

真值不传给召回器。召回器只取得 ASIN、产品图片、文字和正常可发现线索；自然扩展至官网、设计人、申请人后找到号码是有效路径。单纯预填号码直查只验定位能力，不算产品召回盲测。

可信线索承接另作验收：已登记原文中的案号经显式入库、相关性审阅、合并后必须生成正确的单案核验动作并出现在正式候选与报告中；重复导入保持幂等，错国家/类型/号码、未登记来源、身份或文件哈希不符必须拒绝。此测试不能替代产品盲测，也不能证明现行法律效力。

规划回归须用同一组产品输入核对身份词、结构/形状词和已采线索映射；免费备用的“源故障”与“召回不足”分别测试。分页测试至少区分真实零结果、部分阳性、延迟加载、折叠同族及超过首批上限；部分阳性可以证明该条真实发现，但不能证明全查询完整。未审候选和未完成续跑不得通过文件完整性测试被关闭。

`IPR-RECALL-ORACLE/1.0` 包含 `asin`、`jurisdiction=US`、`right_type=patent|design`、`expected_publication_numbers[]` 和 `identity_review={reviewer,reasoning,artifacts:[{path,sha256,source_url}]}`。artifacts 是已经核对的原文/图样；真值与正式 task 及计划分开保存，不伪造未来预期。

## 验证命令与边界

正常执行并归一化候选后运行：

```sh
python3 scripts/verify_recall_acceptance.py --task-dir /absolute/new-run --oracle /absolute/held-out-oracle.json --output /absolute/new-acceptance.json
```

验证器只读取证据：检查同一任务、原始成功召回、计划/回执/截图哈希、原始结果与归一化候选的准确号码绑定，排除已知号码核验冒充召回。返回 passed 仅证明这一测试个案的召回链成立，不证明分类/图像/分页完整，不证明当前有效或侵权。缺少经独立核对的外观真值时该项保持未验收，不拿同名案号填充。

真实执行还需核对：正命中、明确零结果、单案详情、分页和截断、页面变化或访问验证失败。每项按来源×国家×权利×操作记录，不把专利文字检索验收升级成所有外观/商标路线通过。

PPS 单案授权文献与当前登记状态分开验收：Document Viewer 中的案号、标题、页码和实际图像像素逐页绑定。只读到书目页不算附图已读；页码变化但图像未刷新不算下一页。`published_document_only` 只能证明已公开文献，即使全文与附图完整，也不能自动写为当前有效或当前权属已核实。

需要只重试一个计划动作时，使用 `run_browser_plan.py --task-dir DIR --query-id QRY-ID`，仍走正常锁、能力检查、回执和录入链。查询取消记录放在计划的 `execution_dispositions`，必须绑定原查询 ID、完整行哈希与非空原因；扩展保留取消记录。API 与浏览器调度共用同一校验规则，取消不执行、不记为零结果，也不计覆盖完成。

关键负例：外观三条未提交时不得完成；营销长句零结果不得作为有效召回；后续波次未执行须留缺口；原始号码与归一化号码不同须失败；只在号码核验中命中不得通过盲测；专利与外观类型必须一致。历史产物保留，重跑与验收均使用新路径。

## 情景与分流验收：scenario-triage-v1

- 已取得去重候选全量轻量分流，不以“每个候选都有五级评级”验收。大量明确异领域候选不产生完整核验；自动同名／来源 material 标记没有有效入选决定时，不触发正式核验和主体扩展。
- 通用条带、锁盖机构及可靠产品声明关联正例不得被类目、标题或固定 Top N 规则漏选。待补充必须有下一步最小动作，未取得资料仍为待补充，不计排除。
- 同一素材共享不等于跨情景共享结论。换品牌不改变结构专利判断，原卖家身份关联不降低新进入者风险；不同情景审阅不能互相覆盖。
- 单实施方案／独立权利项的有效风险依据必须保留，不能被其他用法不匹配抵消。全失败且无其他依据保持待评，当前风险不能由覆盖缺口机械升高或清空。
- 有效未入选和已审未来信号不报当前漏评；可选提供者失败不阻断已满足义务，真实分页截断仍保留。已取消或过期分流对应的旧动作在调度器和直接 CLI 两处都不得出网。
- 新相关保护内容或身份纠正重新打开对应分流；相同文件重复抓取不重开。明确替代必须有相同范围／目的、新旧查询身份与 hash 和真实完整结果；取消或目标失败本身不关闭必要义务。
- 新目录重建情景、分流和意见，不复制旧意见作为新结论。归档原文保留原取证时间、原哈希与来源，不把旧查询回执改绑新计划。历史复用与新产品盲测独立验收。
- 五项报告必须一致显示情景、预判、置信度、分流／核验／检索完成度及待处理队列。将历史兼容、离线逻辑、报告布局、真实执行与产品召回分别报告，未实测项保持未验收。
- PPS 小结果集必须验证真实定位行：不足一屏、画布留白且折叠为少数专利族时，连续行及已加载范围一致即可读取；只有展开后的实际文献数与官方总数一致才可声明该结果集完整。家族展开增加的显示行数不消耗新分页批次数；真实自动加载、未展开家族、未读虚拟行和时间／分页上限仍保留为缺口。
# 核心图证与专项修订验收

`core-risk-evidence-v1` 需覆盖中/高/极高当前候选、情景隔离、必要产品对照、PDF→页图身份/页码/哈希与显式展示配置；零结果、回执、低风险和未来信号不得进入视觉板。已知风险缺图须显示具体缺口，不能静默消失。

`asset-scope-v1` 验证参考照片不产生拟用摄影义务，拟用包装/图案仍进入版权；非法情景、拼错权利、缺失盘点不等于已审空范围。完成公开调查与未知权属分别记录。DC/DE 真实查询、非零图样、明确零结果和分页分别验收；无适用代码应基于已见图样及官方分类指引标为该轴不适用，不伪造检索。离线编译测试不能替代真实执行。

性能采用同一冻结样本各三次中位数，记录调用次数与输出语义一致性；普通商品运行不重复执行 Skill 开发用 fast/release。单条/批次/恢复、撤销、限流暂停和文件篡改回归仍必须通过。浏览器等待计时不得冒充整轮耗时。
