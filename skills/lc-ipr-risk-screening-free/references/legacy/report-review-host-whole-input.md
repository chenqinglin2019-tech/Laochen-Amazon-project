# 历史整份执行规则

仅适用于没有 `final_review_execution_revision=module-double-review-v1` 标记的历史任务（macOS 沙箱宿主）；新任务不读本文。


在已有 macOS Codex CLI、ChatGPT 登录和系统 `sandbox-exec` 的宿主运行：

```bash
python3 scripts/report_review_host.py --task-dir /absolute/task --output-dir /absolute/new-review-host-run
```

默认使用 ChatGPT 应用内原生 Codex CLI 路径，也可传 `--codex-binary /absolute/native/codex`。宿主先运行只读 readiness；不 ready 时拒绝冻结，并列出需处理的待办。ready 后导出包含 task、evidence、候选、09A 台账、计划、补充证据及 digest 的完整冻结文件，然后创建两个独立临时工作区，运行两次全新、无工具 Codex 会话。两审只收到同一冻结材料；任务目录、宿主输出和另一审阅工作区由 macOS 内核访问规则封锁，宿主在模型调用前实际探测读写边界。

宿主保留每位 Agent 的原始 JSON 和完整事件日志。完整 assessment 原样保留并交 `_validate_review` 验证；格式缺字段、风险没有依据、引用无效或模型调用不完整时拒绝该对审阅，不将其重写成 pending，也不自动重试。compact pending 只适用于仍使用旧 compact 调用的记录器接口，不可用它把完整报告行重新归一化。

连接采用仅本次调用有效的自定义 ChatGPT HTTPS/SSE provider，继续使用现有 ChatGPT 登录，不读取 API key、不改全局配置。关闭 WebSocket、插件发现、MCP 和工具，并关闭请求及流式自动重试；服务连接失败保留日志，由宿主明确报错。原生 CLI 的“Code Mode host 已禁用”固定启动提示只在 turn 开始前允许通过；其他错误和 turn 内错误仍拒绝，不能将连接失败登记为已审阅。

当前原生目录已核实 GPT-6-Astra 支持最大872,000 token；宿主显式选用该模型及上下文窗口，自动压缩阈值800,000，避免默认272,000窗口使大材料无法完整承载。此设置仅影响本次审阅调用，不改用户全局模型。仍保留字符门禁和同源摘要；模型服务若拒绝输入，不通过截断或伪造判断解决。候选评级沿当前selected范围，其他候选核对已有分流与缺口，各适用权利类型另审整体范围。

stdout与stderr从调用开始实时写入宿主日志，另保存 `events.execution.json` 的宿主可见事件时点、真实用量或 null、退出原因。退出码0不是审阅成功；失败、超时和未完成turn保留原始部分日志，登记规则不变。

完整材料审阅每位默认总时限1800秒，`--timeout`可设30..3600秒。总时限与600秒连接空闲时限分别约束整次调用及无数据连接；持续生成不代表已审完，仍须完整turn、字段及证据校验。不要用原来的240秒默认或900秒参数上限反复杀掉正常的大材料生成；达到所选总时限仍保留日志并拒绝该对审阅，不自动重试。

宿主先完成两个工作区的材料、隔离探测和登录检查，再并发启动两次独立原生调用；每位仅收到共同冻结输入，互相不可读取。事件日志各自实时保存，两次执行完成后顺序校验判断，不并发访问判断验证器的共享上下文。

提示契约从真实情景派生allowed_right_types，并列出唯一评级范围、极低/正面冲突的候选与依据要求、未来申请和维权信号的完整引用字段。module_id不同不形成第二个相同范围，未定位未来成员只留整体缺口。输出不合法时继续拒绝，不由宿主替审阅者降级或补造排除依据。

宿主提示与挂载文件使用同一材料视图，只移除重复的 `result_task` 快照及嵌入二进制字段；完整冻结原件和摘要仍保存于宿主目录。提示显式提供当前情景摘要、模块／权利类型映射及证据字段契约，避免审阅者猜测格式；这些契约不替审阅者选择风险等级或填补未知事实。

重复值和对象字段形状使用 `IPR-SHARED-VALUES/2.0` 可读无损编码：`materials` 中的字符串 `"$123"` 指向 `shared_values` 数组第123项（从0开始），`["@",123,...]` 的后续值依次对应 `shared_shapes` 第123项完整字段名；`["!",字符串]` 保留字面字符串，`["!",数组]` 保留普通数组并继续解码其元素。仅一次实际引用的共享定义内联，字段形状仅在净节省字符时共享；所有事实、真实证据ID及原字段名保留，未改变冻结输入或语义摘要。解码继续兼容原 `1.0` 对象引用，循环、缺号和字段数量不匹配仍拒绝。宿主在执行前完整还原并比较原材料视图，同时记录编码及还原视图摘要；提示与挂载文件使用完全相同的编码。超过原生 CLI 单次 1,048,576 字符上限时，在模型调用前明确拒绝，不截断材料或丢弃历史。

原冻结文件及摘要不变；每个工作区另保存 `packet.json`、`prompt.txt` 和注册图片，实际提示及附件纳入各自审计。发送前绑定内存合同及持久化包、提示、隔离文件、挂载视图、图片副本的字节哈希，原生结束后按同一绑定校验；观察门槛使用已验字节解析的发送包，运行中包改写不能重新定义合同或降级 v2。任何变化保留原生输出，拒绝双审成功收据。两审实际收到注册公开原件正文及图片，不只有路径；逐件 `material_observations` 绑定和读取限制按主入口的 `public-originals-v2` 规则校验，不自动迁移历史任务的业务合同。未注册的文件不送审。

两审完成后宿主再次计算实时语义摘要；实质输入变化拒绝登记到旧冻结版本。新冻结可分别通过 `--previous-first-review`、`--previous-second-review` 传各自旧审阅，复用未变化单元的原凭据，受影响单元与总体、范围、限制重审。旧无标记任务保持原整份摘要行为。成功输出目录包含 `frozen-input.json`、每位的 `agent-judgment.json`、`review.json`、访问边界审计和 `freeze-receipt.json`。两份 `review.json` 的宿主执行上下文绑定真实 session、process、workspace、审阅输入摘要和审计文件哈希。

主审在独立文件中完成裁决后，以两份 `review.json` 和 adjudication 调用 `publish_report.py`，使用新 `--output-dir`。发布入口会在创建交付版本记录前再次要求两审 digest 均等于实时 digest；之后仅在新输出目录生成报告。若发布提示实质输入变化，先准备新冻结；v3 两位各自引用未变化单元，不改绑旧签名。旧任务仍按原整对重审规则。

当前任务若 readiness 报告未审材料、可执行搜索或范围待办，必须先沿原 08A/09A 任务处理；本宿主不会自动扩计划、读取任务目录替 Agent 补充判断或放宽 readiness。

原生审阅已完成而个别判断单元未通过字段或引用校验时，不能由宿主改写判断或静默删除引用。已验证的原单元可保存为显式 `registration_scope=validated_unit_subset` 的不完整复用来源，保留原执行、判断与错误单元来源；该文件不能直接发布。纠错审阅仅读取本审阅位自己的原单元，并明确输出补正判断、复用单元及当前总体／范围／限制；仍沿用全部引用、语义绑定与独立性校验。
