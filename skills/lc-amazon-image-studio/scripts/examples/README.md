# Mixed-route job example

`model-native-black-rabbit.job.json` is a production job fragment, not a complete or pre-approved project. Add it only to a reviewed black-rabbit manifest containing the named source and facts; classify its identifying-detail visibility and complete source assessment through the normal pipeline. No model output or approval is bundled.

The model renders the scene, graphic treatment and exactly `job.copy`. `layout` stays empty, so local lettering cannot run a second time. Do not carry an obsolete `generation_geometry_lock` into a newly planned poster. Image-generation return → `ingest` → `review-prepare` follows the normal workflow. The unsigned packet requires an actual text transcription with image-normalized boxes, an unexpected-text inventory and original-size/360px visual judgments. Only after `review-submit` passes may the candidate enter final delivery.

Use `text_mode=local_overlay` with `layout.version=3` for dimensions, FAQ, dense information or exact multi-panel construction. Keep all copy in `layout.text_groups` for this route; do not add `job.copy`. Every image panel must reference its own registered source image. Generated/restored panel references must retain reviewed real-photo provenance, and each panel requires separate provenance, product-identity and crop review. Complete the whole-project `finalize` once before final delivery to refresh overview artifacts.

To reuse four already-reviewed scene rasters without a new model call, use existing `render_mode=pixel_composite`, `placement_mode=manual`, and four visible `product_layers`, each with its registered `reference_id`, matching `asset_path`, truthful `asset_origin`, `opaque_rectangle=true`, and its real `bbox_norm` slot. `crop_bbox_norm` may define an intentional source crop; the cropped image is contained without stretching. Set `layout.version=3`, `recipe=scene_grid`, and place exact local copy in `text_groups`; leave `layout.panels=[]` so the images are not drawn twice. Keep the layout canvas transparent over the already-composed raster. The source assessment must genuinely confirm matching views and clear source pixels. The pipeline derives `layer-0` through `layer-3` review contracts from these actual visible layers, including source/crop/protected-product mappings. The compose command creates the raw artifact and generation binding normally; never set `generated_prompt_hash` by hand.

An explicitly selected missing or changed design reference produces `design_resolution.status=needs_input` with `required=true`. Resolve and prepare it again before dispatch or new composition. Existing raw pixels are preserved, but unresolved reference matching cannot receive a visual-design pass.

New jobs use `generation_dependency_version=2` before their first prepare/generation. This binds critical-detail visibility to the current image only. Older jobs without this field retain their historical fingerprint algorithm. To migrate already-bound pixels, run `migrate-dependencies --manifest project_manifest.json --source-manifest dependency-view.json --source-kind historical_snapshot --jobs IMAGE_ID`. A reconstructed old dependency view must instead be labeled `reconstructed_verified_dependency_view`; it must reproduce an actual ingested attempt's exact generation hash and raw SHA. Migration also proves the old and current per-image scoped generation inputs and prompt bytes are equal. It saves the supplied audit view, preserves historical attempt hashes and raw pixels, and requests fresh QA bindings; it never invents a generation result or increments model calls. A changed current-image scene, copy, source, or required detail is not eligible for this migration.
