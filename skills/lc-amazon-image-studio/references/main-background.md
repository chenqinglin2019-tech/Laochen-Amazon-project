# 主图保守处理与纯白导出

仅适用于 one_pass_v1。新项目的主图带 main_prompt_version=2、main_processing_version=1；没有这些字段的历史主图保留原提示与导出路径，不因升级自动重生或失效。

## 原图处理

- 先在原始分辨率检查 alpha，不先缩放。无 alpha、全透明或无完全透明背景、明显主体触边、整图仅有极弱 alpha 时进入模型专项修复。画布边缘 alpha>16 视为明显触边；只有低 alpha 过渡时允许保留并居中，同时标记 requires_endpoint_check，专项查看必须确认末端没有截断。
- configure 中主图 main_foreground_type 可取 opaque/translucent/unknown，默认 unknown。只有明确为 opaque 时清理背景残留；其余保留全部非零 alpha 像素。此字段不进入生图提示或生成指纹。
- 保护区由全部 alpha>16 的区域扩张短边 0.5% 构成，向上取整且至少 2 像素。不筛掉细线或小配件。
- 仅删除满足全部条件的完整八连通非零 alpha 分量：最高 alpha≤16、与保护区无交集、邻接从画布边缘四连通到达的 alpha=0 区域、面积≤全图 0.002%。像素预算向下取整、至少 1 像素。
- 合计拟删除面积超过全图 0.05% 时不删除任何候选，记录 cleanup_limit_exceeded，交由背景专项查看判断。镂空内部的弱像素不自动清理。
- 以全部保留部件的联合边界整体等比缩放，使宽和高均不超过目标画布 90%，居中摆放。仅去除完全透明的外围空白。采用预乘 alpha 的 LANCZOS 重采样，避免透明像素隐藏颜色污染边缘。

这些规则仅产生候选处理图，不能单凭阈值认定语义正确。特别检查独立挂件、低透明部件、商品白色区域、镂空与接近原图边缘的端点。

## 命令与检查绑定

新主图 ingest-batch 自动准备候选；历史主图使用：

`P scripts/lc_image_studio.py prepare-main --manifest M --job 01_main --json`

- 原始文件保持不变；返回 raw_path、处理图 path、processing_id、attempt_id 和处理统计。相同原图及处理设置重复调用保持幂等。
- 拒绝进行中、提交未知、未解决的瞬时失败或与当前生成输入不符的旧原图。不新增预约，不重置 background_repairs，不释放未知调用。
- 查看原图与处理图后，调用 main-background-check，并传入返回的 processing_id；旧处理 ID 不能批准新结果。旧版未启用处理的主图继续使用不带该参数的原命令。
- pass 后将候选合成到 RGB(255,255,255) 背景并输出 RGB PNG；repair 请求基于最新模型原图继续专项编辑。本地处理不占模型专项预算，最多三次模型专项修复。
- 更改 main_foreground_type 会令已有处理检查失效，返回 prepare-main；它不会触发新商品生成。已有原图、处理文件或绑定哈希损坏时停止交付并处理完整性问题，不通过模型重生绕过。

main_processing 记录处理版本与参数、原图及处理图路径/哈希、等比变换、清理像素数和 processing_id。检查绑定 raw_sha256 与 processing_id；交付还绑定检查摘要。背景掩膜严格来自最终候选 alpha=0，包含外部背景和透明镂空；半透明过渡不计入背景。保存后重新解码逐像素验证纯白，交付时重新核对掩膜与候选来源。

## 历史项目恢复

prepare-main 显式处理已有有效原图，保持原提示版本、生成指纹、预约历史和已用修复次数。旧项目因一次修复上限被阻断且已用一次时，恢复后仍只剩两次模型专项修复。历史已交付图不自动升级；status/deliver 始终只读。附图和 A+ 的导出版本与文件保持独立。
